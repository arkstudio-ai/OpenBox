# 图片用途、画面准备与长视频衔接

适用于所有模型。先读取本次有效模型和实时通道能力，再确认素材用途；模型名、
档次、图片数量、上传顺序均不能代替用户决定。下面是决策内容，不是固定问卷或话术。

## 先确认用途，再选择调用方式

有图片时，正式生成前必须有用户明确的用途指令或真实 `question` 答复。优先复用
当前任务中已经确认、范围未变的决定；个人助理转交的明确决定也有效。只上传图片、
“用这个做视频”、推荐选项、Agent 自己的描述均不能证明用户选择了用途。
用途不明确时先问，结合当前素材自然表达可执行选择，并设置 `allow_attachments=true`。

| 用户确认的目标 | mode | 路径与边界 |
|---|---|---|
| 保留原图整幅画面，让它动起来 | `existing_frames` | 用原资产作首帧；仅在明确需要结束画面时加尾帧，不自动改图 |
| 仅参考人物、商品、环境或风格，另拍新画面 | `reference` | 能力允许时直接用 `reference_image`/`reference_video`；无需中间生图 |
| 先换景、合成或设计新画面，再拍视频 | `prepare_frames` | 说明图片用途、张数和费用，取得对应生图请求；新图集中预览接受后再生成视频 |
| 不使用图片，只按文字生成 | `text` | 不生图；用户拒绝重绘但仍要用原图时不能擅自转成此模式 |

固定确认的是“保留什么、改变什么、是否新增图片”，问法和可选项随任务组织。
不提供当前通道无法执行的模式；说明能力冲突，让用户选择兼容的模型或素材路径。
例如只支持首帧的通道：已有合适画面可直接使用；人物参考图不足以表达目标构图时，
可提出先制作新首帧，不能静默重绘，也不能声称必定需要首尾两张。

逐张确定素材用途：人物身份、商品外观、场景布局、服装、风格或整幅起止画面。
只参考人物，不表示继承原图的桌子、坐姿、机位、光线和运镜。场景参考也要确认
是保留空间布局还是只借用氛围；商品参考按用户需要保留形状、包装和标识。
有多张图时清楚指认人物来源和环境来源，不能按顺序猜首尾、忽略未使用图片。

把已确认用途同时落实到：逐段 `input_assets` 的真实角色、完整提示词和制作记录。
人物身份参考的提示词只约束所需身份特征，场景、动作和镜头按新分镜设计。
`reference_image` 参数配上固定原场景/姿态的文字，仍然会把新画面限制住。
镜头运动、景别与人物动作应服务于当前脚本；固定镜头只是用户可选择的一种设计。

## 长视频：先规划全片，再制作所需画面

确认整条视频的分镜、各段时长、素材路径与衔接方式后，列出真正缺少的图片。
三类路径可以用于不同片段，但必须逐段明确；只有连续的首尾帧片段才采用共享边界。

- **连续场景、连续动作的首尾帧组**：N 段通常用 N+1 张图。三段示例为
  A→B、B→C、C→D，共四张；B/C 必须分别复用同一真实 `asset_id`。
- **换场景或独立镜头**：按剪辑点分别设计；三段若都要控制首尾，通常是六张。
  相同人物不代表相同机位或场景，不能为减少图片数量强行共享跨场景边界。
- **只需首帧**：每段绑定已确认首帧；尾帧可省略。同一首帧能否复用取决于
  用户是否接受每段从同一画面开始；不为了凑两张而自动生图。
- **直接参考生成**：绑定原始参考素材和各段新动作/场景；不额外套用 N+1 图公式。
- **混合长片**：分别计算每个连续组及独立镜头的需求，再按实际资产去重。
  已有、已接受且用途相同的图片可以复用，只为缺少或用户要求修改的画面计费。

在生图前确认整条批准范围的图片数量、逐张用途、衔接方案和已知费用；费用拿不到
就如实说明，不能冒称免费。接受图片不等于同意视频支出，仍需主流程完整分镜与
总费用确认。样片许可只覆盖样片，不扩展成整片生图或视频许可。

有源图时用真实 `image_gen.input_images`，持续引用共同的原始身份/商品来源，
避免只引用上一张衍生图而累积变化。每个不同画面使用对应提示词；`n` 是同一
提示词的候选数量，不能把随机候选当作不同分镜的关键帧。独立图片调用可批量执行，
生成与修改合计每批最多 5 次，每次仍遵守 1–4 张上限；有依赖的步骤按顺序完成。
范围大于一批时分批记录，不能增加单批上限、重复提交已完成调用或绕过费用确认。

整套图片准备好后集中展示并取得真实接受答复，再对批准范围的各段免费估价、
确认完整分镜与视频费用、在通道并发限制内生成。独立视频输入已具备时可以并发；
不要等上一段生成后截取尾帧才开始下一段。保留原有幂等键和任务记录，超时或
结果不明先恢复查询，不能通过重新提交消除等待。

共享静态边界只约束画面端点，不能证明动作、速度、声线和配乐连续。生成后按
`quality.md` 检查每个真实接点，并把问题纳入验收；跨场景剪辑点按所选剪辑方式处理。

## 保存真实决定与失效范围

沿用同一 slug 的 `state.py`。用 `set --key material_plan --value <JSON>` 保存以下内容；
`set` 保存的是 JSON 字符串，`show` 时应按 JSON 解读。字段记录事实，不生成授权。

```json
{
  "mode": "prepare_frames",
  "model": "<当前有效模型>",
  "resolution": "<当前分辨率>",
  "source_uses": [
    {"asset_id": "<真实源图ID>", "purpose": "人物身份", "preserve": ["人物外貌"], "change": ["场景", "动作", "镜头"]}
  ],
  "new_image_count": 4,
  "joins": [
    {"left": 1, "right": 2, "kind": "shared_frame"},
    {"left": 2, "right": 3, "kind": "shared_frame"}
  ],
  "decision_note": "<用户实际指令或问题答复及已批准范围>"
}
```

`new_image_count` 是新增或修改的图片数，复用现有图计零；它不是图像工具调用次数。
每段 `shot --assets` 继续保存实际 `input_assets`/`ratio`；共享帧直接复用同一个 ID。
取得对应用户决定后用 `confirm --kind materials --note <真实决定依据>` 记录用途确认，
不能先写确认再等待答复；图片预览接受情况记录在决定说明中，不能伪造用户验收。
它只是记录本，不代替真正问题卡或费用授权。主流程 `confirm --kind shots` 仍必需。

`state.py check` 会提示用途决定漂移、模式与逐段角色不一致、共享边界缺失或 ID
不一致；退出零仍只是建议。对已有付费任务先恢复原请求，不为新增记录重新付费。

改变用途、源素材、准备范围或模型能力时重新评估，向用户确认发生变化的方案和费用。
换模型不能继承旧模型的补图要求；仍然适用的用户选择和已接受图片可以保留。
修改共享内部帧时更新两侧片段的 `assets`，重新接受受影响图片并重估这两段；
其余已完成片段保留。只改准备说明不能代替更新实际请求。
