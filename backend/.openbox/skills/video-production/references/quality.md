# 生成结果、STT、画面文字与时长质检

生成的人物可能换词、漏词或改变时长，也可能无视 prompt 把台词画进画面。每段都要
展示结果并由用户选择，不能只看相似度后自动决定；STT 只听得到声音，看不到画面。

## 每段检查

App 镜头先用后台 `review` 中的画面文字、转写、实际时长和词时间。旧作业或用户上传的原片可合并提交 `footage_analyze(asset_ids=[...], transcribe=true, word_times=true)`。若个别画面仍有疑点，用该段的资产 ID 补查相应帧。本地工作区路径另可使用以下命令核对对白。

```bash
S=/opt/openbox/skills/video-production/scripts
"$S/extract_audio.sh" shot1.mp4 shot1.mp3
# 通过产品内文件分享获得转写输入，不在聊天中附一摞中间 mp3
python3 "$S/compare_transcript.py" --intended "本段台词" --heard "转写结果"
```

STT 结果卡逐段给出：可播放链接、想说的、实际念出的、相似度与替换/漏念说明、
计划秒数和实测秒数，以及下面的画面文字检查结果。多段拼接还需展示接点检查结果。

## 画面文字检查（每个 take 必做）

2026-10-15 高德生产机（slug crab-voucher，Seedance 2.0 1080p）：5 段 prompt 每段
写了两遍“无字幕”，lint 全过，镜头 1–3 干净，镜头 4、5 却把口播台词渲染成了画面
字幕，而且有错字——“限时”画成“随时”，音频念的是对的。用户选了“不配字幕”，
纯拼接没烧 ASS，card 3 只比对 STT（97.8%/100% 判达标），最终以“纯净无字幕”交付了
一条带错字幕的片子。prompt 里的否定只能降概率，看画面才是验收。

把各段已有的抽帧结果与转写一起呈现。画面文字证据欠清晰时可调用：

```text
video_analyze(action="screen_text", source="<本段资产 ID 或工作区绝对路径>")
```

- 它按约 1 fps 抽帧（每段至少 6 帧、最多 16 帧），不做转写，只问一个问题：画面里
  有没有文字。返回 `has_text=`，以及每条文字的逐字内容（错字照抄）、类型
  （subtitle/title/watermark/logo/scene/other）和出现的秒数；`credits=` 是这次
  视觉调用的费用，要在 card 3 里披露（“画面文字检查已消耗 N 积分”）。
- 同一路径重拍后会重新检查（缓存键含文件 md5），不会拿上一个 take 的结论。
- 工具被拒绝或不可用时，退到 `extract_frames.sh shot4.mp4 shot4_frames --frames 6`
  抽 6 帧，再逐张用 `view_image` 亲眼看；两条路都走不通时，card 3 必须写明
  “画面文字未检查”，该段标 🔴 待用户自查——永远不能把没看过的画面说成“纯净无字幕”。

判定与呈现：

- 意外的画面文字标 🔴。card 3 写出段落、秒数、内容和类型，逐字检查字幕类文字，提供“重拍该段”。
- 已确认的商品广告文字逐字比对本次原画和表单。用整段的定时抽帧检查价格、单位、品牌和口号，留意运动过程中短暂的跳字、变形、裁边或遮挡。某个时刻识别结果有变化时，再查看它的相邻帧。看得见的缺陷标 🔴，修改原画或减少文字附近的运动后重生该段。
- 场景实物上的文字（店招、包装、海报）也照报，由用户决定是否接受；标注类型即可，
  不要替用户判定它“无妨”。
- 用户选了“不配字幕”时尤其不能静默交付：含意外字幕的段应重生或明确接受，
  接受必须由用户明确选择并用 `state.py shot --accept "理由"` 记录。
- 有实证缺陷时先找出来源。参考帧自带字幕、人物姿态不符或海报边缘跳字，先换干净参考或调整运动，再重生受影响镜头。核验服务暂时失败时复核原输出。

## 多段接点检查

逐个查看相邻实际片段的结尾和开头，并检查含接点的短预览。对声音实际试听或用
可用的音频理解能力检查；STT 只能核对台词，不能证明声线、音量或语气一致。
无法检查的项目明确标为待用户试看/试听，不因为素材相同就宣称已通过。

- 画面：面部、发型、衣服、背景、机位及亮度是否突变。
- 动作：手势、身体位置、视线及嘴部姿态是否跳动；句间停顿是否自然。
- 声音：声线、音量和语气是否改变，是否吞字、重复台词或有过长静音。
- 字幕与时长：与被接受的实际口播对齐，接点不丢字，合成后实测总时长。

Turbo 提前准备的共同边界帧只约束两段起止画面；实际输出未必严格复现，且不能
锁定声音。首帧复用模式也可能在每段开始时重置姿态。问题并入原 STT 结果卡，
注明接点对应的两段，让用户选择接受、调整剪辑或重生相关段；不强制增加一轮
质量确认。普通剪辑只能处理适合裁切的停顿等问题，不能用剪辑掩盖换人或换声。

如需换掉预先准备的共同边界图，更新所有引用该图的片段并重新确认图片、方案和
费用；只重生一段且仍使用已接受的同一边界图时，不必连带重做正常的邻段。

## 判定

- `ok`：文本相似度达到 0.90，且没有任何长度的替换词。
- 核对实质漏念、改变商品含义或金额的替换。出现同音异字时，结合听到的音节和上下文核对；音节与授权台词一致时字幕沿用原稿。听不清处标待复核。
- **画面文字 suspect**：存在意外文字，已确认的宣传文字出现错漏、跳字或裁切，或画面文字未检查。
- **时长 suspect**：`abs(actual - planned) > max(2s, planned × 25%)`。
- 标点、空格和嗯/啊/吧等语气填充词不计入文本差异。

文本、画面文字或时长 suspect 的段在卡中标红。用户可选择只重生受影响段，也可以明确接受。
接受时用 `state.py shot --accept "理由"` 记录理由与日期；这是 STT 豁免记录，
不是让脚本替用户放行。字幕使用被接受的实际转写。

## badcase 病理表

| 症状 | 常见成因 | 预防与处理 |
|---|---|---|
| 换人、人物不对、没有采用上传视频 | 人物锚缺失；重写场景过猛；模型/档位不支持参考 | 在支持视频参考的模型上优先原始 person 视频；Turbo 使用已确认首尾帧；不兼容时让用户选模型或素材 |
| 说错话、说梦话、胡嘴 | 台词边界不清；台词过长；后面还接画面描述 | `口播台词：` 后逐字台词并立刻换行；按选定模型边界拆段；逐段 STT |
| 台词前多念“艾特” | prompt 里有 `@`，模型把符号当字念 | prompt 不写 `@`，台词只放在 `口播台词：` 后；原样重试会复现，先改 prompt 并确认修改范围再重生 |
| 打错字、双层字幕、选了不配字幕却有字幕 | 生成端自己把台词画进画面，无视 prompt（2026-10-15 高德 crab-voucher 镜头 4、5，“限时”画成“随时”，STT 全过） | prompt 明写完整否定（画面中不出现任何文字、字幕、标题、水印）并前置 + 每个 take 用 `video_analyze(action="screen_text")` 抽帧检出 + 检到即重拍；后期只烧录 STT 实际词 |
| 背景自己变化 | 场景无锚；质感和装修描述堆料 | 使用 scene 素材或逐字一致的文字基底；场景描述限制一两句 |
| 发型或形象变化 | 身份依据不足；用生成视频截图反复做人物参考导致漂移累积 | 保持共同身份依据；可提前生成并确认首尾图片，不自动从生成视频中提取新的通用人物参考 |

## 重生

只重生有问题的段，并使用新的幂等版本。A `:v2` supersedes `:v1`; one shot
has one current take, and only current accepted takes enter composition. 保留旧文件作为
证据，但不要把同一句的两个 take 都剪进成片。

`state.py shot --job <新 job_id>` 替换已有不同任务时，会把旧 job、文件路径、资产、
转写、实测秒数和接受记录移入该段的 `previous_takes`，清空当前结果字段；当前
方案字段保留。重复记录同一 job 不清空结果、不重复归档。新任务完成后重新写入
其结果并核验，旧 take 的接受记录不适用于新 take。这里只保存历史记录，不删除
旧文件，也不取消已有付费任务。

已确认提交失败且能排除在途作业时，按错误原因恢复。对已完成但有缺陷的镜头，先修正已定位的素材或提示词问题。
重试仍然付费，提交前确认要重做的段数、秒数、模型、分辨率与修改范围，复用已有同范围授权，不再估价。
超时或状态不明不算失败：继续查询同一个已记录任务，不能重复付费提交。

## 合成验收

- 字幕来自每段被接受的实际转写，不来自原稿。
- 每段必须有音轨；成片也必须有音轨。
- 成片实测时长应接近各段实测总和，容差 `max(2s, 5%)`。
- 用户要求约 30 秒等目标时报告实测总时长；若明确要求准确时长，在保留完整台词的
  前提下调整讲稿、停顿或剪辑，不能截断词句凑秒数。改稿仍需遵循原确认流程。
- `state.py check --final final.mp4` 会列出这些问题，但始终返回 0。
- 交付前播放 IMS 返回的最终成片。已在素材中制作的广告文字不在合成层重复添加。

## 计划时长

| pace | chars/s | 适用 |
|---|---:|---|
| calm | 3.4 | 舒缓解释、睡前内容 |
| conversational | 4.0 | 默认教程、评测、科普 |
| energetic | 4.6 | 钩子、促销、倒数 |

每段时长从自己的台词计算，不能用总时长除以段数。模型给多了会填词，给少了会赶
语速。若诚实时长超出用户目标，只能缩稿或明确告诉用户会更长。
