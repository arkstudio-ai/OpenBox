# 生成结果、STT 与时长质检

生成的人物可能换词、漏词或改变时长。每段都要展示结果并由用户选择，不能只看
相似度后自动决定。

## 每段检查

```bash
S=/opt/openbox/skills/video-production/scripts
"$S/extract_audio.sh" shot1.mp4 shot1.mp3
# 通过产品内文件分享获得转写输入，不在聊天中附一摞中间 mp3
python3 "$S/compare_transcript.py" --intended "本段台词" --heard "转写结果"
```

STT 结果卡逐段给出：可播放链接、想说的、实际念出的、相似度与替换/漏念说明、
计划秒数和实测秒数。多段拼接还需展示下面的接点检查结果。

## 多段接点检查

逐个查看相邻实际片段的结尾和开头，并检查含接点的短预览。对声音实际试听或用
可用的音频理解能力检查；STT 只能核对台词，不能证明声线、音量或语气一致。
无法检查的项目明确标为待用户试看/试听，不因为素材相同就宣称已通过。

- 画面：面部、发型、衣服、背景、机位及亮度是否突变。
- 动作：手势、身体位置、视线及嘴部姿态是否跳动；句间停顿是否自然。
- 声音：声线、音量和语气是否改变，是否吞字、重复台词或有过长静音。
- 字幕与时长：与被接受的实际口播对齐，接点不丢字，合成后实测总时长。

Turbo 提前准备的共同边界帧只约束两段起止画面；实际输出未必严格复现，且不能
锁定声音。首帧复用模式也可能在每段开始时重置姿态。问题并入原 STT 结果卡，
注明接点对应的两段，让用户选择接受、调整剪辑或重生相关段；不强制增加一轮
质量确认。普通剪辑只能处理适合裁切的停顿等问题，不能用剪辑掩盖换人或换声。

如需换掉预先准备的共同边界图，更新所有引用该图的片段并重新确认图片、方案和
费用；只重生一段且仍使用已接受的同一边界图时，不必连带重做正常的邻段。

## 判定

- `ok`：文本相似度达到 0.90，且没有任何长度的替换词。
- `suspect`：相似度低于 0.90，或发现替换/漏念。单字替换也要提示，因为
  “出片 → 出花”可能相似度很高但意思已变。
- **时长 suspect**：`abs(actual - planned) > max(2s, planned × 25%)`。
- 标点、空格和嗯/啊/吧等语气填充词不计入文本差异。

文本或时长 suspect 的段在卡中标红。用户可选择只重生受影响段，也可以明确接受。
接受时用 `state.py shot --accept "理由"` 记录理由与日期；这是 STT 豁免记录，
不是让脚本替用户放行。字幕使用被接受的实际转写。

## badcase 病理表

| 症状 | 常见成因 | 预防与处理 |
|---|---|---|
| 换人、人物不对、没有采用上传视频 | 人物锚缺失；重写场景过猛；模型/档位不支持参考 | 在支持视频参考的模型上优先原始 person 视频；Turbo 使用已确认首尾帧；不兼容时让用户选模型或素材 |
| 说错话、说梦话、胡嘴 | 台词边界不清；台词过长；后面还接画面描述 | `口播台词：` 后逐字台词并立刻换行；按选定模型边界拆段；逐段 STT |
| 台词前多念“艾特” | prompt 里有 `@`，模型把符号当字念 | prompt 不写 `@`，台词只放在 `口播台词：` 后；原样重试会复现，先改 prompt 再报价重生 |
| 打错字、双层字幕 | 生成端烧字幕 | prompt 明写“无字幕”；后期只烧录 STT 实际词 |
| 背景自己变化 | 场景无锚；质感和装修描述堆料 | 使用 scene 素材或逐字一致的文字基底；场景描述限制一两句 |
| 发型或形象变化 | 身份依据不足；用生成视频截图反复做人物参考导致漂移累积 | 保持共同身份依据；可提前生成并确认首尾图片，不自动从生成视频中提取新的通用人物参考 |

## 重生

只重生有问题的段，并使用新的幂等版本。A `:v2` supersedes `:v1`; one shot
has one current take, and only current accepted takes enter composition. 保留旧文件作为
证据，但不要把同一句的两个 take 都剪进成片。

`state.py shot --job <新 job_id>` 替换已有不同任务时，会把旧 job、文件路径、资产、
转写、实测秒数和接受记录移入该段的 `previous_takes`，清空当前结果字段；当前
方案字段保留。重复记录同一 job 不清空结果、不重复归档。新任务完成后重新写入
其结果并核验，旧 take 的接受记录不适用于新 take。这里只保存历史记录，不删除
旧文件，也不取消已有付费任务。

真正失败先准备一次 prompt 与参数都不变的重试，以区分生成方差和 prompt 问题。
重试仍然付费，提交前必须重新报段数、秒数、模型、分辨率和预计费用，得到确认。
超时或状态不明不算失败：继续查询同一个已记录任务，不能重复付费提交。

## 合成验收

- 字幕来自每段被接受的实际转写，不来自原稿。
- 每段必须有音轨；成片也必须有音轨。
- 成片实测时长应接近各段实测总和，容差 `max(2s, 5%)`。
- 用户要求约 30 秒等目标时报告实测总时长；若明确要求准确时长，在保留完整台词的
  前提下调整讲稿、停顿或剪辑，不能截断词句凑秒数。改稿仍需遵循原确认流程。
- `state.py check --final final.mp4` 会列出这些问题，但始终返回 0。
- 本地拼接文件用产品内 `share_file` 交付；`video_compose` 成功结果已附成片时
  直接使用该结果，不重复分享。两种路径都要拿到可播放/下载结果才算交付。

## 计划时长

| pace | chars/s | 适用 |
|---|---:|---|
| calm | 3.4 | 舒缓解释、睡前内容 |
| conversational | 4.0 | 默认教程、评测、科普 |
| energetic | 4.6 | 钩子、促销、倒数 |

每段时长从自己的台词计算，不能用总时长除以段数。模型给多了会填词，给少了会赶
语速。若诚实时长超出用户目标，只能缩稿或明确告诉用户会更长。
