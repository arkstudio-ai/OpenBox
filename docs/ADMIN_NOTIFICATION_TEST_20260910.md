# 超管通知测试与移动端默认通知（2026-09-10）

Web 和 iOS/Android 的「超管系统 → 通知测试」支持查看当前手机、App 状态、推送通道、10 种通知文案预览及最近测试结果。远程测试仅发送给超管自己当前登录的手机，延迟 10 秒、每 30 秒一次，沿用前台抑制、后台/离线允许、换机取消旧绑定的规则。通道受理、手机收到、用户点击分别展示，避免将受理误认为送达。移动端另提供本机显示测试。

普通用户和工作空间 owner 不显示通知设置卡片或测试入口；服务端也校验当前数据库中的超管角色。通知默认开启，首次登录后在 App 前台申请系统通知权限；系统拒绝授权或既有明确关闭选择不会被覆盖。前台所有页面、权限弹窗及短暂断网均保持原有抑制规则。

业务事件与测试预览共用短文案模板，涵盖任务结果、待回答/确认、定时任务、重新授权和确认后的发布结果。中文正文最多 36 字符，英文最多 80 字符；任务名截断并清理控制字符。定时失败统一为“未完成，请检查”，不再暗示每一种失败都已重试。具体规则见 [移动通知说明](MOBILE_NOTIFICATIONS.md)。

## 验证与实际范围

后端通知测试 72 项、业务通知回归 18 项及最终文案回归 7 项通过。Web 524 项单测、6 项浏览器测试通过，覆盖 320/390/1280 宽度和明暗主题；类型、国际化及 lint 检查无错误（30 条既有警告）。实际 Nginx 镜像通过缓存、静态文件权限、API、WebSocket 和后端 IP 切换回归，服务器预演校验了 108 个静态文件。

Flutter 319 项测试、静态分析、locale 一致及文件行数门禁通过。普通用户隐藏卡片、默认开启、仅前台首次申请权限、不重复请求被拒绝的权限均有回归覆盖。iOS 模拟器和 Android arm64 debug 安装包已重新构建并安装。

iPhone 17 Pro 模拟器使用已登录超管账号连接 `https://ai.bossipai.com.cn`：前台测试被取消，原因为 `app_foreground`，没有尝试发送；后台两次通过真实 APNs sandbox 收到通知横幅，点击后后台记录 `opened`。最新安装包点击“等待确认”通知后，已实际打开超管的通知测试页。测试没有使用 `simctl push` 或注入通知内容。

Android API 35 模拟器通过真实 HTTPS 验证环境接口 200，以及四个通知测试/回执接口匿名请求均返回 401；测试完成后已装回正常 App。该检查验证网络和接口权限，不代表 Android 极光或厂商离线通道的真实到达已验证。可显式执行：
