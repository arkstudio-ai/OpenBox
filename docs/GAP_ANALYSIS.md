# OpenBox 对 bossip 的差距盘点（查漏补缺）

> 2026-09-02，两仓库各自最新代码实查后的结论。只盘点差距与依赖，不排期。
> 计费方案见 `BILLING_PLAN.md`，网关切换见 `RELAY_CUTOVER.md`。

## 一、你列的四块，逐条核实

### 1. token 计费 —— 确认缺失，方案已有
- OpenBox 只有计量与背压（每步 token、配额 429、视频日限），没有账本/套餐/充值/支付；
  会话累计有 bug（每步覆盖，已开修）、费用估算恒为 0、四处 LLM 调用不记账。
- bossip 有完整一套：plans.config.yaml、rates、UsageEvent/CreditLedger/WorkspaceCreditBalance、
  重试队列、对账任务、后台调账，约 2.6k 行。
- 依赖：每用户网关 token（对账按用户归属）、Workspace/后台（M3 运营面）。

### 2. ECD 新开与池管理 —— 一半有、一半缺，且 bossip 那套不宜原样搬
- OpenBox **已有**：按用户开桌面（EndUser、标签归属、鬼桌面清理、按标签收养、巡检）、
  `cloud_desktops` 表、策略组/镜像强校验、开通 API 与前端状态。上海参数已实测。
- OpenBox **缺**：
  - 每桌面执行通道：provider 仍把所有人路由到共享桌面，`routes_per_user=False` 把 per_user 闸住。
    这是所有桌面相关工作的第一块砖。
  - 池：预热 → 分配 → 试用/付费/内部 → 释放 → 回收（保留登录态）→ 重置（重建镜像）的状态机；
    热池补货、到期 SOP、包月采购纪律（价格比对双门）。
  - 舰队观测：快照采集、13 条对账规则、告警 ack/mute、看板。
  - 交付验证：verify-slot 那种失败即拒的断言集；worker/agent 组件的舰队升级发布。
  - 包月：CreateDesktops 尚未传 period/auto_renew。
- bossip 的实现形态要注意：池管理是 gw-1 上约 1 万行 bash + ECD 标签当事实源，两套标签命名空间
  踩过事故；center 侧另有一套 hermes 时代的 frpc 路径已列入退役。**移植目标应是 Python 服务 +
  DB 事实源**，OpenBox 现有的 `cloud_desktops` + 标签收养是更好的底子，不要把 bash 搬过来。

### 3. 第一方技能市场与发布端 —— 有"技能中心"，没有"市场"
- OpenBox **已有**：技能中心（目录/社区/URL/粘贴/上传安装、agent 创建、发布为快照、下载、卸载、
  MCP 管理）、用户技能库表、沙箱内安装通道、移动端同构。
- OpenBox **缺**：注册中心（不可变版本、内容哈希、ed25519 签名）、语义化版本与 CHANGELOG 定级、
  渠道指针（latest/回滚）、按 workspace 钉版本、平台屏蔽与用户禁用、社区投稿审核状态机
  （草稿→待审→发布/驳回，审核人必须实装预览）、CI 发布链（合 main 即发）、CLI、
  SKILL.md 元数据规范（能力/权限/所有者/注解）与 permissions-map、桌面侧收敛同步（off/shadow/enforce）。
  bossip 这块约 7k 行 + 工具链，是四块里最"可整体移植"的一块，因为它几乎不依赖执行面。
- MCP 市场（版本、渠道、屏蔽、第三方同意书）与之并行，OpenBox 只有 MCP CRUD。

### 4. 授权中心（ECD 登录态管理）—— **两边都没有**，是绿地
- bossip：`PlatformAccount`/`PublishJob` 只有表，没有任何服务实现；登录靠人在桌面 Chrome 里
  扫码，技能明确写"不负责登录"；保全靠"每个付费用户一台常驻桌面 + 回收不清盘"，他们自己的
  差距文档把"登录态供给与保全"列为待设计项。
- OpenBox：桌面 Chrome 专用 profile 持久化在桌面盘上，cookie/登录随盘存活；Chrome 密码库
  未加密；无平台账号模型、无探活、无续登提醒、无撤销、无备份。
- 要定义的范围（建议）：平台账号登记（哪个用户在哪台桌面绑了哪些平台）、绑定流程
  （agent 打开登录页 → 人扫码/验证 → 探活确认）、定时探活与失效标红、续登通知与阻断
  （BLOCKED_AUTH 回到用户）、撤销、profile 快照/恢复（配合桌面回收与数据保留承诺）、
  agent 使用授权的同意记录。它依赖"一人一台常驻桌面"成立，即依赖第 2 块。

## 三、OpenBox 反超的地方（移植时不要退回去）
- 定时任务（cron 14 模块，恢复/回收/预热齐全）优于 bossip 依赖 Hermes 原生 cron 的自动化。
- 记忆系统、资源中心、权限（按工具/技能/URL 的 allow/deny/ask）bossip 没有对等物。
- 浏览器双模式（桌面 Chrome / 用户自己的浏览器扩展）是独有能力。
- `cloud_desktops` DB 事实源 + 标签收养，比 bossip 纯标签驱动的池更可靠。
- 视频原语（幂等、恢复、路由指纹）比 bossip 的分段状态机更收敛。

## 四、依赖关系（排期时的约束，不是排期）
```
每桌面执行通道 ──► per_user 解闸 ──► 池管理 ──► 套餐=开桌面（计费 M2）──► 授权中心
                                          └─► 舰队观测/告警
每用户网关 token ──► 计费对账按用户归属
Workspace + 运营后台 ──► 计费 M3、技能审核、授权中心的运营面
技能注册中心/发布链 ──（独立，可并行）
```

## 五、已拍板（2026-09-02）
1. **授权中心只管登记与活跃检测**（平台账号登记、绑定流程、定时探活、失效提醒与阻断、撤销）。
   profile 快照与恢复**另开模块**，与桌面数据保留一起做，可以复用 action server 的 /backup /restore。
2. **Workspace 进第一版**。计费方案里"旗舰版只能靠积分数区分"的注记作废，团队席位按 workspace 落。
3. **池要预热**：按 bossip 的五态池（预热 → 分配 → 试用/付费/内部 → 释放 → 回收/重置）做，
   但实现为 Python 服务 + DB 事实源，不搬 bash。
4. **技能市场走审核规则评价，但不开放第三方投稿**：第一版只有第一方技能，发布前经过同一套
   规则检查与审核评价（lint、场景测试、权限图、审核人实装），社区投稿入口不做。
