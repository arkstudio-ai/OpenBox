# Light「挑样例」常驻步骤计划

> 2026-11-15 起草，基于 main@b4b54810。状态：§4 六项已于 2026-11-15 全部按推荐拍板；M1–M3 已实现（PR #194 已合），2026-11-15 已发 gw2 `20261115-examplepick-2571d237` 与 App 1.2.0(115)，未真机验证；线上样例库眼下只有做菜单有 2 条可用样例，补库（M4）未做。实现与本文不同之处见 §9。
> 范围：做海报、做菜单、你拍我剪。「做一条视频」暂不动，机制做成通用的，之后可以接。

## 1. 目标

用户选完类型后，从样例库拿三条成品给他看，他点一条最喜欢的，这次制作就按这一条的结构和风格做。
每次进这三个入口都有这一步（常驻），不是只在第一次出现。

要解决的问题：

- 样例库现在只在后台悄悄喂给模型，用户看不到，也选不了，出来的东西像不像他想要的全凭运气。
- 模型同时参考三条，风格会被平均掉。
- 海报和菜单进对话前的样式页是写死在配置里的三四张示意图，不是真实成品，也不随样例库增长。

## 2. 现状（代码事实）

| 环节 | 现在怎么做 | 位置 |
|---|---|---|
| 样例表 | `light_examples`：入口、行业、门店类型、`subtype`（样式 id）、标签、评分、评语、方案卡/提示词、输入输出素材 | `backend/db/models/light_example.py` |
| 挑选 | 入口 → 行业+门店类型 → 行业 → 通用池 → 任意，取前 3；同级按标签重合、评分、时间排 | `backend/light/examples.py` `pick()` |
| 喂给模型 | 三条的标题、评语、方案卡、成品链接拼成「参考样例」段，放进系统提示 | `examples_fragment()` → `light/prompt.py` |
| 类型 | 海报的用途、你拍我剪的成片类型只是开场卡的快捷选项，答案在对话文字里，哪里都没存 | `backend/light/entries.zh-CN.json` |
| 对话上存的 | 只有 `sessions.light_entry` | `backend/db/models/session.py` |
| 进对话前 | 海报 3 个、菜单 4 个固定样式（配置里的示意图）；你拍我剪没有 | `mobile/lib/features/light/topic_gallery_page.dart` |
| 卡片 | `question` 工具带 `step_id`，App 据此点亮步骤条；卡片只有文字选项 | `backend/tool/question_tool.py`、`mobile/.../cards/light_question_card.dart` |
| 后台 | 超管「样例库」：从一次完成的对话预填，团队补门店类型、标签、评分、评语 | `backend/api/admin_examples.py`、`frontend-v2/src/features/admin-examples/` |

缺口：样例没有「类型」维度；三选一没有界面；选中结果没地方存。

## 3. 新流程

三个入口统一成：**选类型 → 挑样例 → 原有步骤**。

| 入口 | 类型（已有的选项） | 挑样例之后 |
|---|---|---|
| 做海报 | 用途：新品上市 / 节日活动 / 开业 / 团购 | 一句话 → 选标题 → 出图 |
| 做菜单 | 样式：简约黑白 / 烟火红 / 手写粉笔 / 深色高级 | 菜名价格 → 核对 → 尺寸 → 出图 |
| 你拍我剪 | 成片类型：探店 / 新品上市 / 活动促销 / 日常记录 | 传素材 → 剪辑方案 → 合成 → 成片 |

样例卡长这样：

- 标题一句话：「这三个是同行做过的，哪个更像你想要的？」
- 三张成品预览并排（图片直接显示，视频显示封面，点开全屏看）。每张下面一行标题。
- 每张一个按钮「就照这个做」。
- 底部一个次要按钮「都不太像，直接做」。

选中后助理回一句「好，照「××」的样子做」，接着走原来的下一步。

边界：

- **不足三条**：同类型不够，用同入口其他类型的补；补完只有一两条就显示一两条；一条都没有就跳过这一步，用户无感。
- **没人在场**：省心托管到点自动做、助理派给帮手做的活，不出卡，沿用现在「自动挑三条一起参考」。
- **「再做一条」**：同一个对话里再做，默认沿用上次选的那条；用户说「换个样子」才重新出卡。
- **旧版 App**：样例卡在旧版上退化成普通文字选项卡（选项是三条的标题），能答、不卡住。

## 4. 已拍板（2026-11-15，全部按推荐）

| # | 问题 | 结论 |
|---|---|---|
| 1 | 菜单没有「用途」这类类型 | 用样式当类型，选完样式给三条同样式的成品 |
| 2 | 进对话前的固定样式页要不要留 | 海报去掉（直接进对话选用途）；菜单保留当作选类型；你拍我剪本来就没有 |
| 3 | 同类型样例不够三条 | 用同入口其他类型补齐，全空则跳过；同时内容团队按「入口 × 类型」补库 |
| 4 | 要不要记住上次选的 | 记：下次同入口同类型时把上次选的排第一并标「上次选的」，仍然出卡，不自动跳过 |
| 5 | 选中的成品图要不要直接当参考图传给出图模型（海报、菜单） | 第一版不传，只给模型方案卡和评语；等验证「照着做」不会把样例的店名价格抄过来再开 |
| 6 | 英文、越南语用户看到的样例 | 第一版不分语言，都看同一批中文成品；样例表先留语言字段，后面再分 |

## 5. 设计

### 5.1 样例库加「类型」

- `light_examples` 加一列 `scene`（可空）。一条 Alembic 迁移，加索引 `(entry_id, scene, status)`。
- `light/taxonomy.json` 每个入口加 `scenes`：
  - poster：`new_item` / `holiday` / `opening` / `groupbuy`
  - footage_edit：`visit` / `new_item` / `promo` / `daily`
  - menu：不新增，`scene` 直接取现有样式 id（`menu_mono` / `menu_red` / `menu_chalk` / `menu_dark`），存量的 `subtype` 回填过去。
- 字段不叫 `work_type`，那个名字已经被 `light/work_types.py` 用作帮手的工作类型。
- `pick()` 多一个 `scene` 参数，排序改成：同类型优先 → 行业+门店类型 → 行业 → 通用池。同类型不够时按原逻辑从其他类型里补。
- 超管样例库：录入表单加「类型」下拉（跟着入口变），列表加类型筛选，加一张「入口 × 类型」条数表，一眼看出哪格是空的。

### 5.2 选中结果存哪里

- `sessions` 加两列：`light_scene`、`light_example_id`（都可空）。同一条迁移。
- `examples_fragment()`：
  - 用户还没选之前，照旧放自动挑的三条（工具万一没被调用，也不会比现在差）。
  - 选中后只放选中的那一条。
  - 用户点了「都不太像，直接做」或把卡片关掉：一条都不放（`light_example_id = "none"`）。
  - 选中的样例后来被停用：退回自动挑的三条。
  - 系统提示因此在选中时变一次，提供商的提示缓存只断这一回。
- 上次选的（拍板项 4）记在用户偏好里：`extra.light_example_picks[entry][scene] = example_id`。

### 5.3 卡片怎么出

新增一个工具 `example_pick`，三个技能在类型答完后调用一次：

- 入参：`scene`（技能把用户的回答归到上面的类型 id）。
- 工具内部：按对话的入口、用户的行业和门店类型、`scene` 调 `pick()`；把类型写到 `sessions.light_scene`。
- 有候选：发一张 `question` 卡，`step_id="example"`，选项是各条标题加「都不太像，直接做」，`detail.light.examples` 里带每条的 `id`、标题、预览图链接、成品链接、类型（图或视频）。等用户回答。
- 回答后：把选中的 id 写到 `sessions.light_example_id` 和用户偏好，返回给模型选中那条的标题、评语、方案卡。
- 没有候选或没人在场：直接返回「没有样例，按技能默认做」，不出卡。

为什么用工具而不是 App 自己插一屏：类型是在对话里答的，卡片得出现在对话流里才连贯；工具走现有的问答卡通道，步骤条、折叠、30 分钟失效、旧版兼容都不用重做。

预览链接是签名链接，会过期。App 重新打开旧对话时卡片已答完，只显示选中那条的标题，不再需要预览。

### 5.4 App

- `light_question_card.dart`：卡片带 `detail.light.examples` 时换成样例卡布局（三张预览、点开全屏、每张一个按钮、底部次要按钮）。全屏播放复用样式页现有的样片播放器。
- 步骤条：三个入口各加一步「挑样例」，由配置下发，App 不用改逻辑。
- 海报专题首页去掉样式选择（拍板项 2）：配置里删掉海报的 `subtypes`，页面自动变成「步骤 + 价格 + 开始」。
- 文案：`light.json` 三种语言各加卡片标题、「就照这个做」、「都不太像，直接做」、「上次选的」。

### 5.5 配置与技能

- `entries.*.json`：
  - poster 步骤改为 用途 → 挑样例 → 一句话 → 选标题 → 出图，删 `subtypes` 和 `text_with_sample`。
  - menu 步骤改为 选样式 → 挑样例 → 菜名价格 → 核对 → 尺寸 → 出图。
  - footage_edit 步骤改为 成片类型 → 挑样例 → 传素材 → 剪辑方案 → 合成 → 成片。
- 三个 `SKILL.md`：
  - `allowed-tools` 加 `example_pick`。
  - 加一节：类型答完立刻调一次 `example_pick`；选中了就按那条的结构、节奏、风格做，不抄它的文案、店名、菜名、价格；没选中按原来的默认规则。
  - poster：样式不再来自开场卡，改成由选中的样例决定，没选中再按用途挑。
  - footage-edit：选中的样例决定四档风格里用哪一档，方案卡上写一句「照「××」的样子」。
- 云电脑上的技能副本要同步（这三个技能不需要云电脑，但技能目录是整包下发的）。

## 7. 风险

- **库太薄**：迁到正式环境时一共 8 条，分到 12 个格子基本是空的。补库不到位时，用户看到的是别的类型的样例，或者这一步直接消失。这是这件事成不成的关键，不是代码。
- **照抄**：只给一条样例，模型更容易把它的文案、店名、价格带过来。规则已有，M1 要加一条对照检查的单测样本，M5 真机验收时专门看这一点。
- **多一步**：每次都多点一下。用「上次选的排第一」减轻，不做自动跳过。
- **提示缓存**：选中时系统提示变一次，那一轮会慢一点、贵一点。
- **你拍我剪的样例是视频**：三条视频预览要加载封面和流，弱网下卡片会慢。封面先出，视频点开才加载。

## 8. 没核实的

- 线上样例库现在各入口、各类型各有多少条（8 条是 11-11 迁移时的总数）。
- 现有 8 条的 `subtype` 填了多少，能不能直接回填成 `scene`。
- `question` 卡的 `detail` 在旧版 App 上遇到不认识的字段是否确实被忽略（代码上看是，没在旧包上试）。

## 9. 实现记录（2026-11-15）

和上文设计不同或补充的地方：

- **卡片走现成的服务端卡片管线**（`question/cards.py`，和「换视频模型」卡同一套），卡片类型 `light_example_pick`，内嵌在对话里。答案在恢复工具调用的同一个事务里写到对话上。语音通话和个人助理都不能代答这张卡（要用眼睛看）。
- **工具** `example_pick(scene, again)`：`again=true` 只在老板说「换个样子」时用，会重新出卡；否则同一对话里再次调用直接返回上次选的那条。
- **预览图**由 OSS 在签名链接上现算：图片缩到 720 宽，视频取第 1 秒那一帧。链接 12 小时有效；App 加载失败时调 `GET /api/light/examples/{id}/preview` 换新链接。
- **`light_examples.pick_count`**：被老板在卡上选中的次数，后台列表里和「被参考次数」并排显示，内容团队能看出哪条真的受欢迎。
- **后台**新增 `GET /api/admin/examples/coverage`（入口 × 类型的启用条数，目标每格 3 条），列表可按类型筛选，`scene=none` 列出还没分类的。
- **菜单**：进对话前选的样式在开始对话时就记成这次的类型（`sessions.light_scene`），所以第一轮就能出同样式的样例卡。老板挑中的样例如果是别的样式，以挑中的为准。
- **迁移** `po5b1c2d3e4f`（接在 `pn4a0b1c2d3e` 后面）：`light_examples` 加 `scene`、`pick_count` 和索引；菜单存量的 `subtype` 回填到 `scene`；`sessions` 加 `light_scene`、`light_example_id`。已在本机 Postgres 上跑过升级、降级、再升级。
- 托管（省心托管到点自动做）和助理派给帮手的活不出卡；帮手房间本来就没有 `light_entry`，托管沿用对话上已经选好的那条。

发布要带的东西：后端镜像 + 上面这条迁移；App 新构建（旧版 App 连新后端时样例卡显示成普通文字选项，能答）。发布后内容团队在后台给存量样例补「类型」，并按条数表补库。

## 10. 样子说明（2026-11-15 晚补）

模拟器走查发现选中的样例对成片影响很弱。原因：

- 模型看不到样例图，只拿到样例当时的出图提示词，截到 1200 字，里面大半是那家店的菜名和价格。
- 技能自带的排版模板（菜名靠左、价格靠右、点线）和进对话前选的样式配色会盖过样例。
- 重试出图时模型会把从样例里学到的那点结构丢掉。

改法（`light/example_look.py`，迁移 `pp6c2d3e4f5a` 加 `light_examples.look`）：

- 让视觉模型看样例卡上显示的那张图（OSS 缩到 1024 宽），写六行「样子说明」：版式、配色、字体、图片、装饰、菜名价格。提示词禁止写出图上的店名、菜名、价格，写完再过一遍清洗（价格和引号里的文字替换掉）。
- 每条样例只读一次，存在样例上。读的时机：后台保存样例后立刻读（记在保存的管理员账号上）；没读过的在样例卡出卡前补读（最多等 40 秒，读不出来不影响出卡）。只读图片，视频样例不读，仍以方案卡为准。
- 老板选中后，工具结果和系统提示里给模型的是样子说明，不再给那段旧提示词，避免把别家店的菜名价格带进来。自动挑的三条（没人选时）不变。
- 菜单、海报两个技能：出图提示词的 Style 和 Layout 两行照样子说明写，配色跟样例走（哪怕和先前选的样式不同），重试时这两行不变；样例有菜品照片时，只给清单上的菜配图。
- 后台接口：样例带 `look` 字段，可人工改；换了主图会清空重读。后台页面还没加这个字段的显示和编辑。

没做：把样例图直接当参考图传给出图模型（§4 第 5 项仍按原拍板不做）。

## 11. 服务端保证这一步（2026-11-15 晚补）

发完 §10 后在模拟器上再走，助理这次没调用 `example_pick`：一次连技能都没加载，直接发了核对卡。同一天三次走查里出卡两次、跳过一次。靠技能说明和提示词保证不了「常驻」。

改法（`light/example_gate.py`）：在入口带「挑样例」步骤、且老板还没见过样例卡的引导对话里，助理一旦发后面的卡（`question`）或开始制作（`image_gen`、`footage_analyze`），这次调用不执行，服务端直接在这次调用上发样例卡。老板答完后，结果回给助理，并告诉它刚才那次调用没执行、现在重新调用。

- 这一步算「已过」的情况：选了样例、选了都不像、样例库没东西可给（记为 `skipped`，之后不再查）。
- 不拦的情况：步骤条上排在挑样例之前的卡（海报的用途、菜单的样式、剪辑的成片类型）；托管等没人在场的对话；没有这一步的入口和普通对话。
- 类型从哪来：对话上已记的类型（菜单在开始时就有）；没有就看老板点过哪个开场选项（海报、剪辑的开场选项和类型一一对应）；都没有就不带类型挑。
- 样例卡已经在等的时候，其他调用被挡回，不会发第二张。
- 这道闸自己出错时放行，不会卡住对话。

## 12. 服务端保证先加载入口技能（2026-11-15 晚补）

§11 发布后的走查里，那个被跳过样例卡的对话从头到尾没有加载 `menu-maker` 技能。出图提示词里因此没有「逐字照录」「不许加菜」的约束，成片多了两道清单外的菜（现炸小酥肉 ¥12、手工蒸饺 ¥10），还编了店名、宣传语和假二维码，也没导出 PDF。入口提示词里那句「开始前先读取技能」同样保证不了。

改法（仍在 `light/example_gate.py` 的同一个钩子里，排在样例卡之前）：引导对话（任何带技能的 Light 入口，包括做一条视频）里，助理发卡（`question`）或开始制作（`image_gen`、`footage_analyze`）时，如果这个对话里还没有成功加载过入口技能，这次调用不执行，返回一条要求：先用 `skill` 工具加载该技能、从第一步照着做，再重新调用。

- 判断依据：对话里有一条已完成、标题为 `Loaded skill: <名字>` 的 `skill` 调用。
- 同一对话最多挡 3 次，之后放行并记日志，避免技能加载不了时把对话卡死。
- 没人在场的对话、帮手房间、普通对话不受影响。
- 没覆盖的：助理纯文字回复（不发卡也不出图）不会被挡；`video_generate` / `video_compose` 没单独挂钩，靠它们之前必有的确认卡兜住。

## 13. 做一条视频也有这一步，且只用视频样例（2026-11-15 晚补）

查线上发现「做一条视频」名下启用的 4 条样例全是菜单设计图（收录时入口随对话带成了视频），它们被当作参考塞进了每个做视频的对话。用户要求：做视频要有专门做视频的样例，并且能选。

- **样例按入口分图片和视频**：`light/taxonomy.json` 每个入口带 `media`（做一条视频、你拍我剪是 `video`，菜单、海报是 `image`）。一条样例只有带了本入口那种成品才算数：样例卡只挑这种的，后台悄悄参考的三条也不再包含放错入口的。没有成品、只有方案文字的样例仍可被后台参考。
- **后台**：保存时，视频入口的样例必须带视频成品、图片入口必须带图片成品，否则拒绝；从对话收录时，如果成品是图片而对话是做一条视频，入口留空让团队自己选。
- **做一条视频加「挑样例」**：步骤改为 选主题 → 挑样例 → 拍照片 → 定讲稿 → 生成 → 保存发布。类型是进对话前选的那个页签（餐品展示 `dish` / 店内环境 `shop` / 探店 `visit`），开始对话时就记下。`light-video` 技能：第一轮先调 `example_pick`；选中后按那条样例的拍法（运镜、节奏、光色、开头结尾）写生成提示词，主体和店名用老板自己的。
- 视频样例不读「样子说明」，以它当时的方案卡和提示词为准（同你拍我剪）。
- 进对话前的固定样片页（9 个样子）保留，作为选类型和默认拍法；样例库里有同类型的视频样例时再出样例卡。两处都要挑一次，是否合并留待看实际使用。
- **线上数据**（gw2，2026-11-15）：原先挂在做一条视频下的 5 条菜单设计（4 条启用、1 条停用）已改到做菜单，改前的行备份在 `backups/20261115-example-entry-fix/video-examples-before.jsonl`。做一条视频现在 0 条样例，要内容团队收录真正的视频成品后才会出卡。
