## 0. 一页结论

| 问题（跑市场的反馈） | 方案 | 核心取舍 |
|---|---|---|
| 销售介绍太长，黄金 5 分钟抓不住人；特色功能（AI 视频、发布、定时运营）演示不动 | **A. 首条视频引导**：开屏 → 登记「你的店」→ 选模板 → 拍一张照片 → 出一条 15 秒竖屏视频，带店名花字。免费，固定走灵活档 MiniMax-H3 768p，不进 agent 多轮对话 | 用确定性流程换掉 agent 的三张确认卡；只送 15 秒（秘塔 16–30 秒单价翻倍，成本 1.35 → 3.6 元） |
| 小老板的认知止于豆包，不懂「交办 agent」；输入框面前不知道说什么 | **B. App Light 模式**：底部 tab + 一页功能按钮（第一版聚焦餐饮：做视频〔店内环境 / 餐品展示 / 探店〕/ 做菜单 / 做海报为主入口，发抖音 / 成绩复盘 / 掌柜为次入口；「省心托管」是贯穿所有任务的能力，不是入口），每个按钮进一个**对话专题页**：顶部步骤条，agent 用卡片一步步问，用户点选为主、随时可打字。背后仍是真实会话与技能 | Light 是设置项：新注册默认进，老用户手动切；视频默认省钱档；入口和步骤文案由后端下发，改文案不发版 |
| 客户怕 AI 视频贵 | **C. 你拍我剪**：用户传手机实拍，agent 看素材、听人声、出一张「剪辑方案卡」，确认后交阿里云 IMS 合成。按成片条数收费，不按 IMS 分钟数 | IMS 本身极便宜（720p 售价 0.045 积分/分钟），利润在「看懂素材 + 出方案」；定价与 AI 生成拉开档位 |

三件事的共同底座：**后端下发的「入口/模板」配置**（§4.3）和**不依赖云电脑的免费档路径**。免费档没有云桌面：A 只用后端直连的 `video_generate` / `video_compose`，天然不碰 sandbox；C 今天的素材分析（`video_analyze` 采帧、`video_transcribe` 抽音）都在桌面里跑 ffmpeg，后端镜像没有 ffmpeg，所以 M3 要先把这三步搬到 IMS / DashScope 侧（§5.4 第 1 条），否则你拍我剪只能对付费用户开放。

## 1. 市场反馈转成产品问题

1. **第一印象是输入框。** Web `/app` 首页是问候语 + 三张静态卡 + 输入框；App 多了三屏介绍和欢迎 sheet，但同样落在输入框上。对一个只用过豆包的老板，「说清目标，AI 会追问」等于把工作推回给他。
2. **特色功能藏在对话里。** 发抖音、定时运营、热点改编、经营数据全部要靠说对话才能触发；销售现场没有一个可以指着点的东西。
3. **第一条视频的路径太长。** `video-production` 技能按 C5 规则要走「讲稿卡 → 素材卡 → 合成卡」三张确认卡，每张都要用户读完整内容再点；这对老客户是保护，对新客户是劝退。
4. **价格焦虑没有被正面回答。** 价表里 AI 生成从 0.17 到 8.30 积分/秒，老板算不过来；而我们最便宜的产出（IMS 剪辑）根本没有入口。
5. **免费档无法展示发布链路。** 免费档没有云桌面，`desktop_publish` 直接返回 `SANDBOX_SUBSCRIPTION_REQUIRED`。首条视频能做出来，但「发到抖音」必须变成升级钩子，而不是报错。

## 3. 方案 A：首条视频引导

### 3.1 用户看到什么（App）

| 步 | 屏幕 | 用户做什么 | 耗时目标 |
|---|---|---|---|
| 1 | 开屏 | 现有三屏介绍压成一屏：一句定位 + 一条 15 秒示例成片自动播放 + 「免费做一条你的店的视频」按钮；注册/登录在按钮之后 | 30 秒 |
| 2 | 你的店 | 行业（餐饮 / 美业 / 零售 / 其他）、店名、主打一项（招牌菜 / 主推项目 / 爆款商品，一个输入框）。三格，都可跳过 | 40 秒 |
| 3 | 选模板 | 三选一：**招牌推荐**（主打特写）、**门店氛围**（环境 + 人气）、**活动促销**（节日 / 新店 / 折扣）。每张带 5 秒示例片段与一句说明 | 15 秒 |
| 4 | 拍一张 | 「拍一张或从相册选一张（招牌菜 / 门头 / 商品）」，H3 用它做参考图；可跳过改纯文字生成 | 30 秒 |
| 5 | 制作中 | 进度条（按历史耗时估算）+ 三张能力卡轮播：「做好后一键发到抖音」「每天定时帮你做一条」「你拍我剪，实拍也能出片」。可以退到后台，做好推送 | 1–3 分钟（待实测，§3.5） |
| 6 | 成片 | 竖屏播放、「保存到相册」、「发到抖音」（免费档 → 开通套餐页，带「发布需要云电脑」一句话）、「换个风格再做一条」（进「做视频」对话专题页，附当前成片与提示词）、「去首页看看还能做什么」（进 Light 首页） | — |

规则：

- 全程**不出现模型名、档位、积分/秒**。只在成片页右上角一个小字「本条免费 · 之后约 4 积分/条」。
- 任何一步跳过都能继续；步 2 跳过时用行业通用模板。
- 整个流程只跑一次；完成或跳过都写 `user_preferences.extra.onboarding.first_video = {status, job_id, session_id}`。设置 → 账号的「重新查看新手引导」不重跑生成，只重放介绍。

### 3.2 系统做什么

```
App/Web 表单 ──► POST /api/first-video {industry, shop_name, headline, template, asset_id?}
                   │  1. 读模板（§3.3）拼提示词；行业/店名/主打回写 assistant_profile.business 与 onboarding
                   │  2. 创建会话（source=first_video，标题「我的第一条视频」），落一条用户消息（表单摘要）
                   │  3. 复用 video_generate 的 submit 内部函数：model=档位 low 解析出的模型、768p、9:16、15s、
                   │     input_assets=[reference_image]、幂等键 first_video:{workspace_id}
                   │  4. 返回 {job_id, session_id, eta_seconds}
客户端轮询 GET /api/first-video/{job_id}（复用 video_jobs 行）
                   │
完成 ──► 现有链路：拷 OSS → settle_generation → _attach_completed 写 FilePart
         ├─ 可选步：video_compose 叠店名 + 一句 slogan 的花字（现有 TextClip + AlibabaPuHuiTi，+1 张 IMS 作业，约 20–30 秒，0.045 积分）
         ├─ source=first_video 的会话不走 resume_conversation 唤醒 agent，而是写一条固定助理消息
         │   「这是你的第一条视频。想改风格、换文案，直接告诉我。」并附 3 条 next-step chips
         └─ 推送：新模板 first_video_ready（App 推送 + 消息中心），深链到成片页
```

- **不走 agent。** 提示词是我们写死的模板，不经过 `video-production` 的三张确认卡，也没有 LLM 回合费。首条视频的质量靠模板打磨，不靠模型即兴。
- **会话仍然建。** 成片落在一个真实会话里，「再做一条」「改一下」从这里进入 agent，上下文（成片、提示词、店名）都在，这就是「背后还是对话式支撑」。
- **免费档没有桌面也能跑。** `video_generate` 与 `video_compose` 都是后端直连供应商，不需要 sandbox。

### 3.3 模板与提示词

- 位置：`backend/.openbox/skills/video-production/references/first-video-templates.json`（随技能走，桌面同步不受影响；首条视频只在后端读）。
- 维度：行业 4 × 模板 3 = 12 条提示词，每条含：镜头描述（H3 擅长的特写 / 推拉 / 环境光）、禁止项（**画面不出现任何文字**，H3 会画错字；不出现人脸特写以避开真人审核）、参考图用法（有图：「以这张图里的 X 为主体」；无图：行业通用主体）。
- 店名与 slogan **不进生成提示词**，只走 IMS 花字叠加（§3.2 可选步），这样字永远是对的。
- 时长：**15 秒**。秘塔通道 16–30 秒单价翻倍，成本从 1.35 元跳到 3.6 元（20 秒）；10 秒（0.9 元）太短不像成片。
- 验收前每条模板实跑 ≥3 次，淘汰出片率低或画面与行业不符的写法；模板 JSON 带 `verified_at`。

### 3.4 赠送与计费

现状已经能免费：无套餐工作空间每周懒发 10 积分，一条 15 秒 H3 售价 3.75 积分。两种做法：

| 做法 | 代码量 | 账单可见性 | 风险 |
|---|---|---|---|
| (a) 直接用免费档周额度 | 0 | 账单上看不出「送了一条视频」 | 用户先聊天花掉额度，首视频提交时余额 ≤ 0 被拒（提交前只查余额 > 0） |
| (b) 一次性 `signup_gift` 发放 4 积分 | 约 10 行：`db/repository/user_repo.py` 建工作空间时 `post_ledger(kind="signup_gift", key="signup_gift:{workspace_id}")` | 账单一行「新人首条视频」，销售可以说「注册就送」 | 积分仍可被聊天花掉；多开账号薅 4 积分（成本 1.35 元/个，可接受） |

**建议 (b)**，并在 `POST /api/first-video` 里对余额不足的情况直接放行一次（按幂等键 `first_video:{workspace_id}` 只放一次），把「送一条」兑现成硬承诺。真实成本：H3 1.35 元 + IMS 花字 0.03 元 + 推送 ≈ 1.4 元/新用户。

### 3.5 需要先量的数

- **H3 15 秒出片耗时。** 仓库里没有实测；配置是 5 秒轮询、180 秒提交超时、13 次内联等待后转后台补扫。M1 第一周先在 gw2 用 `video_generate` 跑 20 条 15 秒 H3，记录 p50/p90，等待页的进度估算与「超过 N 秒改推送」的阈值由此定。验收线：p90 ≤ 3 分钟；超过则等待页默认引导「做好了通知你」而不是干等。
- **参考图出片率。** 招牌菜照片、门头照片各 10 张，统计被审核拒绝与画面跑偏的比例，决定步 4 是否默认展开。

### 3.6 复用与新增

- 复用：移动端引导的 `OnboardingController` / `GuideQueue` 与 `onboarding` 偏好存储；`assistant_profile.business`；`video_generate` 的 submit/轮询/落盘/计费链路；`video_compose` 的 TextClip；消息中心事件与推送；成片 FilePart 渲染。
- 新增：`api/first_video.py`（两个接口）；模板 JSON；App 六屏；`signup_gift` 发放；`first_video_ready` 通知模板；`source=first_video` 会话的完成处理分支。Web 版本后续再做（接口不变，只补页面）。

## 4. 方案 B：App Light 模式——功能首页与对话专题页

> 2026-10-27 拍板：只做 App；Light 是设置项，新注册默认进，老用户在「我的」里手动切；视频默认省钱档；先画交互原型再开发。决策逐条见 §4.7。

### 4.1 设计原则

1. **按钮即任务，不是功能说明。** 每个按钮对应一件 10 分钟内能拿到结果的事，按钮文案是动词。
2. **专题页就是一个被功能引导的对话页。** 点「做视频」进的不是表单，而是一个只为做视频而生的对话：顶部是这件事的步骤条，对话流里 agent 用卡片一步步问（选主题、定讲稿、确认价格），用户大多数时候点选项，随时可以打字插话；成片以结果卡出现，带「保存 / 发抖音 / 再做一条」。背后是一个真实会话加对应技能，卡片就是现有 `question` 确认卡与文件卡换了一层 Light 皮肤。
3. **不限制问几步。** 流程需要多少信息就问多少，但每一步只问一件事，能点选的不让打字。
4. **Light 隐藏的是选择，不是能力。** 模型只露「省钱 / 标准 / 高清」三个词，**默认省钱**（MiniMax-H3 768p）；不露 build/plan 模式、思考强度、技能目录；价格按整条算给用户看，不显示每秒单价。
5. **入口、步骤、开场卡文案、默认档位、价格提示都从后端下发。** 放后端 JSON 文件，改文案发后端不发版；后台编辑页先不做。
6. **专业界面一个都不删。** `user_preferences.extra.ui_mode = light | pro`。

### 4.2 App 信息架构

Light 模式下 App 改为底部四个 tab（专业模式保持现有抽屉导航不动）：

```
首页   对话   消息   我的
```

### 4.4 对话专题页的结构（四个入口共用一套组件）

```
┌ 顶栏：‹ 首页 · 做一条视频 · 步骤条 [1 选主题] › [2 定讲稿] › [3 生成] › [4 发布]
├ 对话流
│   agent 卡片：开场卡（本入口固定文案）/ 选项卡（单选、多选芯片）/ 确认卡（内容 + 价格 + 「就这样」「改一下」）
│               / 进度卡 / 结果卡（视频、图片、链接 + 动作按钮）
│   用户气泡：点选结果以气泡回显（「招牌推荐 · 拍了一张 · 15 秒 · 省钱」）
├ 底部：上下文输入条 = 当前步骤的快捷芯片 + 文本框 + 相机 / 相册 + 语音
└ 任何时候可以打字插话；agent 回到流程时步骤条跟着走
```

- **步骤条的来源**：入口配置里的 `steps[]`；agent 每张卡带 `step_id`，前端据此点亮，不靠前端猜。
- **卡片协议**：复用 `question` 工具（单选 / 多选 / 确认）与 FilePart，只给消息加一个 `light` 元信息（`entry_id`、`step_id`、`kind`），不新增消息类型。专业模式打开同一个会话，看到的是普通确认卡。
- **开场卡不等 LLM**：`POST /api/light/start` 创建会话时直接把入口的开场卡写成第一条助理消息，用户点选后的第一次 `prompt_async` 才开始花钱。
- **技能层感知**：`ui_mode=light` 与 `entry_id` 进系统提示词；`video-production` 在 light 下三卡合一（对 C5 规则的明确例外，记入 `C5_VIDEO_SKILL_ALIGNMENT.md`）；其余技能不变。
- **工具轨迹**：默认折叠成一行「正在做：生成视频」，用轨迹简明模式的工具中文字典（`admin-trajectories/lite`）做映射，不复用页面。
- **插话**：用户打字后 agent 照常回答，答完回到当前步骤重新发卡；步骤条不回退。

### 4.5 接口与配置

- `GET /api/light/entries`：入口列表，每项 `{id, title, subtitle, sample_media, steps[], opening_card, availability: ok | needs_plan | needs_desktop | needs_binding, price_hint, default_tier}`。`availability` 由后端按套餐、桌面、登录态算好，前端只渲染。
- `POST /api/light/start {entry_id, project_id?, context?}`：创建会话、写入开场卡、返回 `session_id`；之后走现有 `prompt_async`，带入口默认的 `video_model / video_resolution` 与 `light` 元信息。
- `GET/PUT /api/auth/me/preferences`：加 `ui_mode`；注册时写 `light`。
- 配置文件 `backend/light/entries.json`（版本号、每入口的 `steps[]`、开场卡、芯片文案、默认档位）。

### 4.6 与已有计划的衔接

- ROADMAP E2「空白对话引导页重构」在 App 侧由本方案的首页替代，`workspace.suggestions` 静态卡在 Light 模式下不再使用。
- OPS_CASE M1 的 `stores` 表合并后，首页顶部店名与「做一条视频」的默认主题改读 `stores`，starter-cards 接口直接喂首页「今天可以做」区块。
- autopilot 预算模板的表单化就是「省心托管」的三问卡，顺便解决「模板只能对话创建」。
- Web 后续做时复用同一套接口与 `entries.json`，只补页面。

## 5. 方案 C：你拍我剪

### 5.1 用户看到什么

| 步 | 屏幕 | 说明 |
|---|---|---|
| 1 | 对话专题页开场卡 | 成片类型四选一：探店 / 新品上市 / 活动促销 / 日常记录；示例成片各一条；价格一句话「60 秒以内成片 X 积分」 |
| 2 | 传素材 | 相册多选 3–10 段（也可以一段长的），每段 ≤ 200 MB、总时长 ≤ 5 分钟；可选加几张照片；上传进度逐条显示 |
| 3 | 说要求 | 一个输入框：「想突出什么、什么调性」，可空；可以粘贴自己写的拍摄脚本或口播稿 |
| 4 | 剪辑方案卡 | 一张卡：成片时长、镜头顺序（每段用哪几秒、为什么）、字幕 / 花字文案、BGM 风格、口播（如有）、**总价**。可改时长、删镜头、改文案，然后「就这么剪」 |

### 5.2 系统做什么

```
上传完成 ──► /api/assets/complete 新增：对 video/* 做媒体探测（时长、宽高、方向、编码、是否有声）写 file_assets.meta
                                     （后端 ffprobe；或 IMS RegisterMediaInfo + GetMediaInfo，二选一，§5.4）
专题页「生成方案」──► POST /api/light/start {entry: footage_edit, asset_ids, type, brief}
agent（技能 footage-edit）
   1. 读 file_assets.meta 拿每段时长与方向；横屏素材标记「将居中裁 9:16」
   2. video_analyze 逐段看内容（镜头、主体、可用片段起止）；有人声的段落 video_transcribe 出字幕
      （今天这两步都要桌面里的 ffmpeg；§5.4 第 1 条改成不依赖桌面之后才能对免费档开放）
   3. 按成片类型的结构模板（探店 = 门头 → 环境 → 招牌 → 价格/活动 → 收尾）挑片段、写字幕与花字、选 BGM
   4. question 工具出「剪辑方案卡」（一张，含价格）
用户确认 ──► video_compose submit（timeline：shots 用 asset_id + in_sec/duration_sec，captions，texts，audio）
          ──► 完成后 settle，按 §5.3 计价；FilePart 进对话；推送 footage_edit_ready
```

### 5.3 定价：按成片收，不按 IMS 分钟收

IMS 720p 售价 0.00075 积分/秒（0.045/分钟），成本 0.03/分钟，这部分一条片赚不到一分钱；真实成本在看素材（Gemini 视频输入按专业档计）、听人声（fun-asr 0.05/分钟）与出方案的 LLM 回合。

建议两行计价，都复用现有「按单位报价 + 完成后结算」机制：

| 项 | 售价（建议，待拍板） | 我们的成本（估） | 实现 |
|---|---|---|---|
| 素材分析 | 1 积分 / 分钟素材，不足 1 分钟按 1 分钟 | 视频理解约 0.1–0.2 元/分钟 + ASR 0.05/分钟 | `rates.json` 新增 `media.footage-analyze`；`video_analyze` / `video_transcribe` 在 `footage_edit` 流程里按此结算，不再按 token |
| 成片 | ≤ 60 秒 5 积分；≤ 3 分钟 9 积分；每再加 1 分钟 +2 | IMS 0.03–0.06 元/分钟 + 推送 | `rates.json` 新增 `media.footage-compose` 阶梯；`settle_compose` 在 `kind=footage_edit` 时按阶梯而不是按秒 |

对照：5 分钟素材剪成 60 秒成片 = 5 + 5 = **10 积分**；同样 60 秒用 AI 生成是 H3 15 积分、Wan 720p 84 积分、Seedance 1080p 333 积分。专题页就用这组对比回答「AI 视频贵」。

方案卡上的价格是确认前的报价，确认后不再变；素材分析在出卡前已发生，所以**出方案本身要先收素材分析费**（卡上写明「已含分析费 N 积分」），用户不剪也不退——与「上游扣了就收」的既定原则一致。

### 5.4 要补的能力（按依赖顺序）

1. **素材处理搬离桌面**（免费档开放的前提，也是 M3 最大的一块）。今天 `video_analyze` 用桌面里的 ffmpeg 采帧、`video_transcribe` 要先在桌面 `ffmpeg -vn` 抽音，后端镜像（`backend/Dockerfile`）没有 ffmpeg。三步各找云端替代：
   - 探测：上传完成时 IMS `RegisterMediaInfo` + `GetMediaInfo` 拿时长 / 宽高 / 编码 / 有无音轨，写 `file_assets.meta`（同账号 OSS，顺手拿到 MediaId）。这也补上 `video_compose` 报价需要 `duration_sec` 的缺口。
   - 采帧：IMS 截图任务（`SubmitSnapshotJob`，按秒抽帧到 OSS），再把帧交给现有的视觉理解提示词；`video_analyze` 加一个 `source=ims` 分支。
   - 转写：优先验证 DashScope fun-asr 能否直接吃视频 URL；不行则用 IMS 的 ASR 任务，或 IMS 转码出音频后再喂 fun-asr。
   不想做这一条的话，备选是把 ffmpeg 加进后端镜像在后端进程里跑，但这与「不养渲染机」的既定取舍相反，且 5 分钟素材的采帧会占住后端 CPU；不建议。
2. **音轨**：`timeline.py` 加 `audio: [{asset|library_id, from_sec, to_sec, volume, fade}]`，编译到 IMS `AudioTracks`；原声与 BGM 两轨，口播段自动压低 BGM。BGM 来源二选一（§7）。
3. **竖横处理**：横屏素材编译时 `fit=cover` 居中裁；HEVC / mov 先在 IMS 侧确认可直接作为 MediaURL 输入（spike 只验过 mp4）。
4. **技能 `footage-edit`**：结构模板（四种成片类型）、片段挑选规则（动静结合、每镜 2–4 秒、开头 1 秒必须是主体）、字幕规范（每条 ≤ 14 字、与口播对齐）、方案卡格式、只允许 `video_analyze / video_transcribe / video_compose / question / share_file`。
5. **口播（可选，二期）**：用户没录人声时按脚本 TTS 配音；需要接 TTS 并作为音轨之一，先不做。
6. **价格文案修正**：`video_compose.py` 工具 schema 与 `references/compose-timeline.md` 里的 0.03/0.06 是成本价，改成售价口径。

## 7. 风险与开放问题

| 风险 | 应对 |
|---|---|
| H3 出片耗时超过 3 分钟，销售现场冷场 | M0 先量；等待页按实测写进度；超阈值走推送；销售话术里把等待时间用来讲三张能力卡 |
| 参考图被真人审核拒绝（门头有人、菜里有手） | 模板提示词避开人脸；被拒时自动降级为纯文字生成，不让用户重来 |
| 免费档每周 10 积分 + 4 积分赠送，被批量注册薅 | 成本 1.4 元/账号；先确认 Logto 注册是否强制手机号（代码里没看到短信逻辑）；不强制就加设备指纹 + 同设备只送一次 |
| Light 单卡确认与 C5 三卡规则冲突 | 只在 `ui_mode=light` 放宽，金额上限仍由 `credit_cap` 兜底 |
| BGM 版权 | 候选：IMS 公共媒资库的音乐（需确认授权范围）或自备 20 首无版权曲库放 OSS；二选一前 M3 的方案卡先只做「原声」 |
| IMS 固定 25fps、无字幕底框 | 实拍素材多为 30fps，IMS 重采样可接受；字幕用描边；若产品坚持底框，这是切 Remotion 的触发点（见选型文档 §5.3） |
| 免费档没有桌面，「看经营数据」「发抖音」入口在 Light 首页是灰的 | 灰卡写清楚缺什么、一键去开通；这正是把套餐价值摆到台面上的地方 |
