哪些地方限制了 Agent

画廊模板的分镜由模型编写，但一按「开始生成」，后端就只给它一个 light_gallery 工具。海报、逐段 ComfyUI 和阿里云合成都在这个工具的同一次调用里执行。高级界面能展示内部进度，但 Agent 在这一轮很难临时插入一次转写、选乐或镜头检查。

入口或模块当前行为改造决定
画廊里的三个愿望渲染只暴露 light_gallery。其输入恰好五段，参考方式来自固定枚举。先用它试点。把五个剧情节拍、参考片和海报经验迁到 Skill，开放已有媒体工具。
丝路留香、苏打水、早就吃上了、商品商业片准备和渲染经过 light_wan_story 的不同参数定义。旧 wan_story 草稿也走这条路径。逐模板迁移其转场、声音、画幅和质量要求。分别验收复杂商业片与超宽画幅。
这单谁买提供 light_remake 和工具搜索。分镜生成代码仍含请客、趁热吃等餐饮台词。先区分样片台词与买家指定台词，再为不同品类编写适合的改编例子。
自由生成及其他品类自由视频已能组合多种媒体工具。实拍剪辑、菜单和海报各有自己的工具集合。自由视频用作对照组。此次迁移范围是复刻视频。菜单、海报和旧主题页单独管理。

还有三处需要一起处理

  • 通用视频工具依赖具体模板。 video_generate 的模板参数仅接受 gallery_wishes，ComfyUI 第 4 镜还有旧第三愿台词校验。新流程应让经确认的对白跟随本次分镜，旧草稿仍能读回其指定台词。
  • 运行结束和成片交付有两个判断点。 Agent 循环用两个专用工具的 guided_action_finished 提前收口。App 另从任务回执、作业和附件推导状态。只改工具名单，两端可能会对同一任务给出不同结论。
  • 高级自定义入口没有独立的逐轮凭据。 制作按钮已有后端写入的来源。高级自定义借用普通聊天页面与发送接口，?from=production 用于返回导航。现有高级结果还会按同会话的人类消息、时间和附件关系筛选。

把创作、执行和窗口更新接起来

同一个 OpenBox Agent 继续负责整条视频。一键制作从已确认的表单直接开工，高级自定义可以调整方案、查看真实调用。另一个用户从模板中心开始时，会创建自己的制作单，复用作者发布的拍法，使用自己这次选定的商品与素材。

Agent 自己决定

哪段要迁移原片动作，哪里值得做宣传原画，是否需要语音识别、字幕或配乐，哪个失败镜头可以局部修复。镜数和分段随确认的剧情、节奏和模型能力调整。

服务端负责兑现

验证当次素材归属、选择的模型、可用参数和已授权范围。快速档 H3 使用项目的加速图。最终剪辑走阿里云 IMS。作业恢复、并发、额度和成片归属由后端执行。

开放工具的代价

现有总控调用能在一轮模型决策之后并行拍摄多段。拆开后，每次选工具都可能增加模型往返时间和上下文。建议一键入口先给出模板的默认节拍与素材索引，已确定输入的独立镜头允许并行提交。查状态由作业恢复机制承接，普通成功步骤省去额外通知。用户仍能一次提交，只有需要重新决策的部分才回到 Agent。

一个模板怎样适配不同商品

《画廊里的三个愿望》的原片解析记录了 37.93 秒的动作与反转。值得复用的是观众如何看懂愿望逐步升级、人物如何被商品替换。店名、商品、报价和逐字对白取自当前制作单。

Skill 应该装什么

模板 Skill

主文件写剧情结构、关键动作、改编自由度和验片要点。参考文件按节拍索引原片、关键帧、时码和可借用的镜头语言。每次制作固定模板版本。

通用视频 Skill

写素材角色、质检、选乐、实测字幕与 IMS 交付。把仅适用旧主题页的问答流程、工作区脚本和重复确认限定到原入口。表单已确认的决定直接复用。

模型 Skill 与适配器

comfyui-h3 放原生对白及首帧、首尾帧、视频和声线参考的写法。适配器执行实际 Workbench 图、素材角色绑定和参数校验。模型说明可供既有授权场景复用。

读入方式。 后端只为本次选中的发布版本挂载简短说明。需要某段动作时再解析对应的共享素材为当前工作区可用的资产 ID。官方和社区模板走同一份清单格式，作者发布新条目后无须在通用工具里增加枚举。模板示例和用户输入都标记来源。

镜头怎么拍，由当次目标决定

  • 需要精准复刻抛竿、提灯和人物反应时，传该段 reference_video。需要换商品时再传当前 reference_image，分别说明动作来源和商品身份。首帧适合从明确画面出发，首尾帧适合两个指定画面之间的可见过渡。
  • 同一角色跨段说中文时，使用 H3 原生对白标签。支持该组合的参考模式可复用已确认的独立 reference_audio。转写核对漏字和错词，声线连续性另做听审。镜头无对白时保留现场声选择。
  • 用户需要对白字幕时，按 video_transcribe 的实测时间填写 IMS 时间线。用户选择配乐时调用 music_search。动态广告里的品牌与报价随生成画面进入剪辑。

当前快速档工作流的核对项包括 DMAD LoRA 0.8、Euler 10 步、SelfLift 第 6 步切换和低分倍率 0.6。首帧、首尾帧和 R2V 保留同一加速链，按真实素材选择条件输入节点。RunningHub 暂停期间，已有任务可查，新拍摄遵守当前启用的模型路由。

专业版用户怎样把作品做成模板

建议在专业版成片卡提供「做成模板」，也支持在当前对话说“把这条视频做成别人能用的模板”。Agent 负责提炼拍法，作者能在同一页修改、换商品试用和决定公开哪些内容。完成一次后，下一位作者可以自行走完全程。

菜单和 Skill 中心各提供了什么

已核实的实现可以直接借用视频模板还缺什么
菜单的在线样例库App 从 /api/light/examples 拉分类、预览与样片，制作时只引用用户选中的条目。后台已能从成品读取参考卡。样例收录端属于管理员，记录里还保留来源会话与原资产引用。为普通作者新增按所有者鉴权的草稿入口，复用预览组件与内容分析函数。
专业版个人 Skill 与商店skill_manage 已支持 create 和 export，可建立个人归属和文本包。Skill 中心已有显式发布、审核开关、撤回和上架反馈。模板需要成片提炼、媒体资源清单、按版本试用及精简版消费。现有「上传 Skill 压缩包」只安装到沙箱，上传成功本身不产生商店发布记录。
「做一条视频」的复刻选择器保留现有模板卡片、作品预览、商品输入和制作按钮。Flutter 内置视频模板名、字段及档位分支，后端也校验固定名单。两端一起改为读取已发布模板的描述，才能在相同安装包上使用新条目。

一个创作 Skill 搭配一个草稿工具

建议增加 OpenBox 内置的 video-template-author Skill，指导 Agent 提取可复刻要素。专业版用户启动这次模板创作后，再提供一个 video_template_draft 工具，负责解析选中来源、保存或修订私有草稿、校验并生成预览。复用现有个人 Skill 封包和所有权服务，模板草稿按类型存放。公开发布沿用 Skill 中心的用户确认与审核服务，创作页可以直接调用。这两个动作使用各自的回执。

  1. 只提取选定成片用过的内容

    从当前用户有权使用的最终资产反查 IMS 时间线、被采用的镜头版本、时码、转场、原生对白和经过确认的文案。作品来自外部、只有一个 MP4 时，用抽帧与转写提炼可见动作和可听节奏，把推断标为“从成片推断”。作者可以补充原片参考和拍法。

  2. 把本次产品改写为下一位用户的输入

    以小龙虾广告为例，保留“画家擦灯 → 愿望升级 → 烟雾中揭晓商品”。把餐馆名、虾的照片、45 元一斤、口号和指定台词映射到使用者的对应输入。模板可描述“揭示报价”，当新用户将价格留空时，Agent 采用无报价的收尾。示范成片里的商品只出现在作者选择的公开预览里。

  3. 区分「给人看的样片」和「给模型用的参考」

    让作者在同一张预览卡上看到封面、公开样片和可跨账号复用的参考片段。比如只分享手部抬起的动作，可截取中性片段。如果旧商品始终占满画面，就只保存节拍或重新制作中性参考。人物声线、原片、音乐和商标素材分别标记可共享范围。使用者的商品图由其本人选择。

  4. 先在私有草稿里验证替换效果

    作者可换一张测试商品图，直接预览表单、已解析的镜头和素材角色。常规校验不提交视频作业。需要看实际效果时，作者可选择试拍一个镜头或完整生成。改好后在专业版点「发布到模板中心」，一次确认这次提交的文本和媒体范围。

生成的模板包长什么样

SKILL.md                 拍法、动作因果、适配与验片说明
template.json            表单绑定、媒体角色、兼容能力与格式版本
references/beats.md      节拍、时码、可复用动作及推断来源

媒体在发布时生成版本专属资源清单，记录稳定资源标识、用途和摘要。封面、预览、可执行参考各自交付。大视频放在受控媒体存储，执行时换取当前任务可读的资产。模板文本与媒体均可独立校验。

例如清单可声明 kind=video_remake 与 schema_version=1，把商品图绑定到 asset_ids，把报价绑定到 promotion_brief.offer。App 按格式版本判断能否解析这份清单。作者可以在同一格式下发布内容 V2，新旧作品分别绑定各自使用的内容版本。

公开包只带作者选定的创作说明和可共享资源。后端按成片归属提取使用过的素材，在媒体登记时校验读取及分享权限。获准公开或复用的媒体存为发布版专属副本，清理作者的临时生成目录或刷新预览签名都不会切断模板引用。对话全文、废弃镜头和私有资产留在作者工作区，登录凭据和 ComfyUI Token 由平台认证与模型适配层管理。社区包提供声明式数据，工具权限、加速节点与 IMS 交付规则继续由平台控制。

依据 菜单样例与作品提炼个人 Skill 创作及上传现有复刻选择器

发布到模板中心，让其他用户直接用

建议让「模板中心」成为 Skill 中心里视频模板的分类视图，专业版发布页和精简版模板库读同一个上架版本。创作者管理「我的模板」。使用者可以在「做一条视频」看样片、点「使用模板」并填写现有表单，也可以在专业版新对话中选用同一版本，自行改编。

两种上传方式，共用一条发布链路

从专业版成片生成。 草稿已经保存在作者的私有模板库，点击发布时直接提交核对过的版本，无须手动下载、转发 ZIP。从已有模板包导入。 在「我的模板」上传自有的包和要共享的媒体，预检格式、文件与资源清单，建立私有草稿后走同一发布动作。安装他人的模板保留原作者归属。如果原作者开放二次创作，可另存为自己的派生模板，记录父模板与来源版本。

服务端需要提供什么具体做法
一个条目，多份可追溯版本条目保存稳定模板 ID、作者及工作区。每次提交保存不可变的发布版本，包含包摘要、媒体清单摘要和校验结果。分别记录当前公开版本和待审候选。现有 UserSkill.published_* 会在新提交时更新，单靠这组字段无法同时恢复旧版和审核新版。
一次审核，两处同时生效沿用已有部署的审核配置、作者撤回和运营下架。需要审核时，审核动作绑定候选版本及摘要，通过后在同一事务切换公开版本。配置允许直接上架时，通过校验的提交可直接完成切换。Skill 中心和精简版的列表、详情、下载与新建制作统一检查条目的可见性及作者状态。
按版本动态渲染表单拟新增 GET /api/light/templates?entry=video 返回分页卡片和兼容版本。详情返回字段绑定、必填性、媒体角色及模型能力要求。客户端用现有商品图、品牌、商品名、报价和创意文案控件渲染。创作者的“第三愿”等个性需求可以进入创意文案，新增控件由产品设计统一决定。
使用者按次加载用户选中时保存 template_ref（条目、发布版本、摘要）。后端校验可见性和能力，按需载入该版本，并将允许的共享参考解析给当前制作。模板中心只向界面返回卡片，与模型上下文分开。用户无须把社区模板逐个安装进沙箱。

接口落点（拟议）。 专业版草稿工具和 POST /api/templates/drafts/import 共用同一个草稿验证器。POST /api/templates/{id}/submissions 接收已预览的草稿版本、摘要与请求 ID，所有媒体就绪后才登记这次提交。版本变化就返回最新差异，重放同一请求返回原回执。审核通过时递增目录版本，App 回到模板库或主动刷新即可读取新卡片。显示旧缓存时，点用仍向服务端核对可见性。

新版待审时，模板仍然可用

例如甲的 V1 已上架，乙正在用它制作。甲提交 V2 后，需要审核的环境仍公开 V1。V2 被退回时甲可以继续修改。V2 上架后，新选择使用 V2，乙已经受理的任务继续按 V1 的包和素材完成。普通撤回或下架会关闭新的使用请求。若特定素材授权被撤销，则单独停用该资源，受影响的续作提示重新选择。

实现时给视频模板接入同一个版本解析服务。审核员打开候选版本，用户打开当前已上架版本，后台恢复已受理任务时凭原回执读取固定版本。旧公开版本、候选新版和作者草稿各有明确读者，审核一个版本时不会把另一个版本的字节交给使用者。

哪些更新可以免发版。 首次上线通用模板协议、后台读取器和 App 动态选择器后，增加一种新剧情、换样片、调整节奏、改模板说明或发布作品的新版本，都走内容发布。同一 App 构建和后端部署即可收到。新增一种平台尚不支持的表单控件、模型输入或工具能力时，才按需升级对应客户端或后端。旧客户端通过协议版本过滤自己无法消费的条目。

依据 发布服务与审核策略快照与上架状态App 兼容入口

通知工具只在哪些回合出现

把「精简版不能分栏」落实为一个可验证的产品入口。屏幕变窄、复制链接、在同一个会话说“我是从精简版来的”，都只能影响界面或消息文字。后端受理本条消息时记录的入口才决定工具权限。

用户如何进入本轮通知工具后端判据
精简版点准备或制作开启首版仅为「做一条视频」启用。沿用制作动作接口写入的来源，关联当前制作单、表单版本、动作回执与执行代次。
制作页点「高级自定义」核实后开启新增制作专用高级消息入口。由已认证制作页取得限时入口凭据，逐条验归属、版本与请求标识，再生成服务器端回执。
专业版或普通聊天，含同一会话不提供普通发送接口沿用原工具权限。曾进过精简版、能读到历史对话或看见旧通知都不构成本轮授权。
专业版选「做成模板」或提出同一请求不提供核实来源作品归属后，本轮可用模板创作 Skill 和草稿工具。发布权限按作者和发布操作核验。创作模板与写入精简版任务通知分别授权。
复制高级页链接、切换分栏、后台 Agent不提供导航参数和布局只影响显示。已受理作业由后台继续记录真实结果，新的普通回合重新按入口判定。

工具解析要守住三个位置

  1. 创建本轮上下文。 复用权限系统，将制作凭据绑定用户、工作区、制作单和草稿版本。它表达的是制作入口权限。用户同时在专业版另发的消息拥有独立回执。入口凭据留在 App 与后端，模型只得到校验后的能力。
  2. 构建工具和 Skill 目录之前。 仅向符合条件的回合注入通知工具。初始工具、延迟发现、按名恢复、远程目录刷新及后续步骤使用同一过滤条件。只在当前模板的上下文中合并其 Skill，缓存视图包含入口和模板版本。普通回合不增加这项工具的 schema、搜索条目或系统提示。
  3. 真正写入时。 再校验本轮已领取的回执、当前执行代次、制作单与版本。后台续跑通过原作业关联更新事实。合并收信或租约交接时只能继承同一已核实制作的上下文。通知工具的授权不能扩大媒体工具权限。

建议的接入点。 现有 backend/assets/video_templates/ 可提供官方模板的首批导入包。运行时从模板中心解析本次选中的发布版本，按回合加入 Skill 解析器。普通聊天不会因为中心多了一千个模板而增加一千项模型输入。高级入口可新增 POST /api/light/productions/{id}/advanced-entry 与 …/{id}/messages。前者创建限时入口凭据，后者复用现有受理队列、附件归属校验和客户端请求去重。凭据过期后从制作页重新进入。

窗口通知怎样送达

建议新增一个小工具 light_production_notify。它只传用户值得知道的一句创作说明。常规进度、待确认项和最终成片都有各自可信的来源，Agent 漏报一句说明也不影响交付。

{
  "kind": "repair_note",
  "shot_id": "s3",
  "text": "上一次手部遮住了商品，这次保留抬手动作并调整了构图。"
}

拟议入参为类型、可选的当前镜头标识和短文本。类型先支持 repair_note（修复原因）与 decision_note（创作取舍）。接收人、制作单、版本、重拍批次和事件序号均由服务端确定。

用户看到什么事实或文字由谁提供窗口怎么处理
已提交、生成中、片段可预览该制作单绑定的真实作业、当前有效镜头版本和可读资产。更新镜头卡。总镜数在方案保存后出现，完成数按有效镜头去重。
为什么换参考或重拍Agent 调用上述通知工具，后端核对镜头和本轮范围。对应镜头增加一行说明。相同操作重放沿用同一通知，后续新一版可以有新说明。
需要你选包装色或改文案已有 question 的待答记录，或 light_production_form 的待接受提案。展示一个有效操作，答复回到原问题或提案。用户确认前暂停依赖此决定的步骤。
可以播放最终成片后端核对本次选定的最终 IMS 作业、当前剪辑版本和已就绪的成片资产。给出播放和保存。聊天文字、说明通知、单个片段以及预览合成都无权把制作页置为完成。

首版先复用现有 GET 与轮询

将短说明存入制作域，按逻辑制作、操作/镜头版本和说明类型去重。工具重放返回原记录。把精简摘要、最近说明、待确认项和单调递增的 view_version 加到现有制作详情。写说明、资产绑定与推进对应的视图版本应在各自事务中原子完成。

制作页现在只在工作中或分镜编辑活跃时每 3 秒刷新，且在高级页期间暂停。首版保留这条路径，返回高级页的上一级、App 回到前台、等待用户选择时也要按当前任务补拉。App 只接受同一制作单、同一草稿版本内更新的视图版本。后续若需更低延迟，可在事务提交后通过现有 WebSocket 发「该任务已更新」提示，丢包或重连仍以 GET 补齐。

两个界面各显示什么。 精简版显示「第 3 镜正在重拍」和原因。高级自定义展开后显示真实的 video_analyze、video_generate 等调用及其结果。已有后台作业的多次等待可归到同一作业下。用户不需要读原始工具日志才知道下一步。

怎样自主修复，又能安全续做

一次制作可以跨多个 Agent 回合、租约和 App 重启。稳定的制作标识要贯穿到底，每次写入则验证当前回合。这样续做能接回已付费的作业，旧回合的迟到回执也有明确归属。

最少需要记录的关联

记录建议的实现
制作单与输入快照在现有制作记录中保存稳定的逻辑制作 ID、输入版本、模板版本、执行方式和用户确认的范围。素材 ID/角色、商品、品牌、报价、逐字对白、模型档位和画幅可重放。显式留空的价格继续留空。
镜头与作业记录镜头 ID、拍摄版本、输入指纹和对应的图片操作或 VideoJob。沿用真实 provider 任务 ID 和幂等键。回执 ID、Agent run ID 与执行代次另存，用于验证当前写入者。
最终剪辑绑定在制作专属上下文中给 IMS 提交标明「预览」或「交付」，登记选定的作业和剪辑版本。后端校验时间线输入属于本次允许的素材及有效镜头，作业成功且资产归属正确、可读后发布结果。更换镜头会使依赖旧版本的最终候选失效。
读视图与短说明制作详情读取快照、有效镜头、最终候选和待答项。说明按操作保存，推送只携带任务标识与版本。复用现有作业和资产表，新关联不得与已有 VideoJob.production_id 指向的业务实体混用。

把问题分成可以直接修，以及需要人做决定的情况

  • 参数校验失败。 Agent 读取校验详情，更正素材角色、提示词或时间线，并在原范围内重新校验。素材无法读取时重新解析有权读取的同一资产。
  • 等待超时或提交结果不确定。 先用真实作业 ID 和原幂等键对账。进行中就继续等待，成功就取回同一资产。上游是否接单仍不明时，保留阻塞原因和原始任务，暂停新提交。
  • 画面或对白偏差。 用分镜对照、画面检查和转写定位受影响镜头。既有授权覆盖该次重拍时，给受影响镜头创建新版本，复用已通过镜头。新增付费重拍、变更指定台词或切换模型超出本次授权时，走已有提问或提案。重复确认同一范围会打断一键体验。
  • 取消、换产品或迟到回执。 终止本轮新提交。上游仍回来的结果归档到原操作。新制作单重新绑定本次商品图和原画，时间线只接受有效版本。服务重启后从快照选择待办步骤。

等待期间由谁把下一步接起来

让已有作业恢复器按原任务号查询提供方并写回结果。当一批依赖镜头都已就绪，后端以「制作单 + 剪辑版本 + 待办步骤」生成唯一唤醒键，投递给原制作任务。若 Agent 此时仍持有执行权，就合并到这一轮。并发完成三段也只触发一次待剪辑步骤。恢复时跳过已完成的图片、片段和合成作业。

目前画廊的每日可提交量预检会读取模板固定的镜数。改为从本次已确认计划计算还要提交的有效镜头，扣除可复用作业，并沿用配置中的额度与逐次提交校验。这样六个镜头的计划与三个镜头的计划会按各自的实际需求受理。

交付的判据。 「准备」完成看当前版文案或分镜是否已保存。「渲染」完成看当前版最终 IMS 作业和资产。记录待答、可恢复阻塞或已取消作为各自的结果。Agent 正常结束时若尚有在途作业，App 继续显示制作中，并由作业恢复机制接续。

依据 幂等作业与恢复现有状态投影IMS 与成片

先改交付判据，再开放工具

按新建制作单和模板逐步切换。创建时固定执行版本，避免一条付费任务在新旧两套执行器之间来回切换。

  1. 建立基线，做只读对照

    选择画廊、一个非画廊模板和自由视频的可用历史样本。记录当前启动方式、作业数、成片来源、工具上下文与窗口状态。用已有记录重放新投影，比较两种判定，先排清预览、旧附件和迟到作业的差异。

  2. 落地任务绑定、入口和通知

    后端补制作单/镜头/成片的关联与高级消息入口，再实现专属通知和 GET 摘要。移动端接入版本去重、返回刷新与待答跳转。现有执行器仍能产生事实，用它验证整条通知链。

  3. 用画廊跑通统一模板格式与动态选择器

    将画廊作为首个官方模板导入版本库，让前后端从同一描述读取卡片、字段、能力和参考资源。兼容旧模板名、旧草稿和旧客户端。把专用工具提前收口替换为可恢复的通用完成判据，再开放有权使用的媒体工具，按用途处理片段投递和作业唤醒。

  4. 打通一位作者到另一位使用者的完整路径

    先上线专业版成片转私有草稿与换品试用，再接通模板包上传、原有审核后台和模板中心索引。由普通测试账号甲独立提交新模板，账号乙在同一版本 App 中刷新并使用。此项通过后再开放更多创作者。回退时可暂停新投稿或暂停指定模板的新制作，按正常版本策略处理在途任务。

  5. 扩展到其余活跃模板

    逐个移植样片解析、关键转场与独有验片规则。当前代码对「丝路留香」和苏打水屏蔽 ComfyUI 快速档，原因涉及超宽或自适应请求。两者先验证参考角色、画幅和最终裁切，再调整能力声明。product_story 现有分镜编辑投影也有专门分支，需单独验收。

  6. 退出旧执行器

    灰度开关按模板只控制新制作单。关闭新入口时让已受理任务按原版本继续或恢复，保留旧草稿、历史成片和回执读取。活跃旧任务归零、历史回放通过后，再退役单模板专用工具和冗余提示词。

第一版的两次验收。 先证明官方画廊模板可以自主复刻、按真实作业更新精简版。再在模板中心基础能力上线后固定 App 和后端构建，让普通专业版作者从零发布一条新模板，由另一个账号用自己的素材完成制作。团队可以直接用这次跨账号结果验收“加模板免发版”。

版本审核与撤回固定乙的 V1 在途任务，依次测试 V2 待审、退回、通过、撤回，以及并发更新时迟到的审核结果。另测关闭审核的配置。每个入口看到同一个有效版本。旧审核结果不能放行其他摘要。普通撤回阻止新使用，乙的既有任务按已绑定版本恢复。新增协议能力只向兼容客户端提供。

效果指标如何读

用相同表单、模型、分辨率、时长和参考模式对比新旧链路。分别记录首个有效预览时间、GPU 排队与生成时间、Agent 等待与工具轮次、IMS 耗时、成功交付率、重复提交数、局部重拍数和普通会话新增工具描述 token。这样才能分辨变慢发生在模型、队列还是 Agent 编排。创作质量另由人对照原片和本次商品评审。

建议把串品、错误完成、重放导致的重复计费、普通会话新增专属工具条目四项设为零容忍。任一项出现就暂停扩大灰度。生成耗时和 Agent 轮次先采集同条件基线，再决定可接受的变化幅度。

模板中心单独记录普通作者独立完成首次投稿的比例、模板上架到另一个账号能选用的延迟，以及另一账号用不同商品完成第一条成片的比例。指标按模板发布版本记录，便于定位问题发生在提炼、分发还是制作。
