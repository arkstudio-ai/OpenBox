## 1. DeepSeek Harness 的现有界面

### 1.1 截图对应什么

用户截图是选中一条 `TOOL` 记录之后的右侧详情面板，位置是 `Turn 1 · Step 1`。它包含 `Summary / Payload / Result / Schema / Timing` 五个页签。

截图打开的是 `Timing`，当前展示三项：

| 字段 | 截图内容 | 含义 |
|---|---|---|
| Started | `2026-08-13 22:29:43.983` | 这条工具记录的开始时间，显示到毫秒 |
| Duration | `1,814 ms` | 工具记录的耗时 |
| Timing source | `Session timestamps` | 耗时来自会话记录的时间戳 |

本地代码支持点击开始时间，在本地日期时间与 Unix 秒时间戳之间切换。顶部色条是轨迹时间线的一部分；仅凭这张局部截图不能确认该工具的名称、参数或结果。

### 1.2 不同记录使用不同页签

Harness 的记录类型是 `system / user / context / compacted / message / tool / subtool`；另外还有可选中的模型请求分组。模型请求和它产生的 Assistant 消息是两个不同的检查对象。

| 检查对象 | 实际页签 | 主要内容 |
|---|---|---|
| USER 用户输入 | Summary、Preview、Raw；存在来源时增加 Source | 来源、状态、时长、内容预览、原始内容块、图片、来源 JSON |
| CONTEXT 上下文注入 | 同 USER | 注入的内容与来源，例如插件或目标推进输入 |
| ASSISTANT AI 回复，内部 kind 为 `message` | Summary、Preview、Raw；存在来源时增加 Source | 状态、输出 token、推理/正文细分、正文、返回的 reasoning、图片、工具调用块、来源请求链接 |
| TOOL 工具调用 | Summary、Payload、Result、Schema、Timing | 父级关联、状态、实际参数、返回内容、调用时工具定义、起点和耗时 |
| SUBTOOL 子工具调用 | 同 TOOL | 额外提供父工具与 Assistant 消息的层级跳转 |
| SYSTEM 初始系统状态 | System Prompt、Tools | 生效的系统提示词、完整工具目录 |
| SYSTEM 系统状态更新 | Diff、System Prompt、Tools | 系统提示词/工具目录的前后差异及更新后完整值 |
| COMPACTED 上下文压缩 | Summary、Raw Output | 状态、耗时、摘要、原始压缩输出；该记录的 token 项目前显示占位 |
| Request 模型请求分组 | Summary、Options、Usage、Timing | provider、model、状态、工具数量、错误与重试、请求选项、用量和请求计时 |

工具的 Payload、Result 页签在对应内容非空时才出现；模型请求未记录选项时不显示 Options。Assistant 的请求计时显示在概述中，并能跳到所属 Request 的 Timing 页签，不能把截图中的五个工具页签套到所有记录上。

当前 `Options` 的类型字段是 `provider`、`model`，以及可选的 `purpose`、`thinking`、`reasoningEffort`、`temperature`、`maxTokens`、`stop`。`Usage` 同时展示本次请求和会话累计，包含输入、缓存读取、缓存写入、其他输入、输出、推理、内容；只展示已提供或可按其口径计算的值。

Assistant 的计时字段是 `Started / Total duration / TTFT / Generation / Throughput`。这里的首 token 时间指首个非空文本、reasoning 或工具调用增量；并不只指第一段正文。工具的 Timing 则是截图中的三项。

## 2. OpenBox 的超管后台页面结构

### 2.1 入口与使用路径

使用路径为：**超管系统 → 轨迹监控 → 跨用户会话列表 → 会话轨迹详情 → 选中具体记录**。

平台超管使用现有 `role=admin` 和 `RequireAdmin`。普通用户的聊天页不增加轨迹 tab，工作区 owner/admin 也不因此获得平台超管权限。未授权直达 URL 由前端守卫拦截，后端独立拒绝其接口和实时订阅。

| 页面 | 目标路由 | 作用 |
|---|---|---|
| 会话监控列表 | `/app/admin/trajectories` | 跨全部用户、全部工作区筛选会话 |
| 会话轨迹详情 | `/app/admin/trajectories/sessions/:sessionId` | 查看所选用户会话的实时轨迹与历史回放 |

新增 `features/admin-trajectories`，由现有后台路由装配；通过该 feature 的公开入口提供列表页和详情页。通用组件从 shared 复用，不横向引用普通 Chat 的执行 store 或业务接口。

### 2.2 跨用户会话列表

默认显示所有用户中已有记录的归属会话，按最近记录活动倒序。列表一行对应一个会话，点击标题或“查看轨迹”进入详情。用户筛选是可选条件，不要求先逐层进入一个用户页面。

| 列 | 展示内容 |
|---|---|
| 用户 | 用户名、用户 ID；邮箱可作为辅助信息和搜索项 |
| 会话 | 会话标题、session ID |
| 工作区 | 工作区名称/ID，便于区分跨工作区会话 |
| 运行状态 | 运行中、等待用户、空闲、异常等当前业务状态 |
| 记录状态 | 已开始记录、未记录、有缺口、记录故障；与运行状态分开 |
| 最近活动 | 最近记录活动时间，可排序；会话创建时间为可选辅助列 |
| 记录起点 | 首次开始记录的时间，旧会话也显示真实起点 |
| 模型/Agent | 最近实际请求的模型与主 Agent；多模型标记后可在详情查看 |
| 执行数量 | 已记录请求数、工具调用数；失败/未知按对象类型分别统计 |
| 用量 | 已记录范围内输入/输出 token；不混用上线前的会话累计 |
| 操作 | 查看轨迹；有记录时可直接进入实时或回放位置 |

默认保留用户、会话、运行/记录状态、最近活动和查看操作，其余列可按宽度折叠。筛选包含用户、标题/ID、工作区、运行状态、记录状态、活动时间范围；支持服务端搜索、分页、刷新和一键清空筛选。

列表只请求摘要，不获取各会话的完整 prompt 或事件。新活动可提示“列表有更新”；浏览历史页时不自动重排行。列表筛选/排序/分页写入 URL 或页面状态，进入详情再返回后恢复；不通过切换登录身份或活动工作区实现用户筛选。

可选择“包含未记录会话”，此时展示现有 Session 元数据和“尚未开始记录”。点击只读详情不会创建日志或触发执行。委派产生的子会话默认在父会话轨迹中展开，不重复生成列表项；拥有独立轨迹的会话单独列出。

### 2.3 单会话轨迹详情

进入详情后采用类似 DeepSeek Harness 的布局：上方时间线，下方执行列表与可调整宽度的右侧详情面板。保留超管后台导航和返回列表入口，为详情提供足够的宽屏空间。

| 区域 | 必须展示 | 交互 |
|---|---|---|
| 会话信息栏 | 目标用户名/ID、工作区、会话标题/ID、记录起点、运行/同步状态、当前统计范围 | 返回列表、回到实时、打开回放、导出 |
| 统计概览 | 已记录请求数、工具执行数、失败/未知数、输入/输出 token、运行耗时 | 展开细分口径；统计显示对应水位 |
| 时间线 | 请求、工具、等待和子 Agent 的时间区间；用户输入、恢复等时点 | 点击定位、缩放/聚焦；区分等宽浏览与实际时长 |
| 记录列表 | 类型、摘要、状态、所属 Agent、Turn/Step/Request、开始时间、耗时 | 搜索、筛选、展开父子关系、选中详情 |
| 详情面板 | 类型标题、层级面包屑、按类型生成的页签 | 查看完整内容、复制字段、跳到关联记录 |
| 回放控制 | 播放/暂停、倍速、逐事件、前后 Step、当前位置、实时最新位置 | 按 seq 跳转；可选择跳过空闲等待 |

列表默认保持紧凑：类型与内容是主体，状态/Agent/时间作为辅助列；窄屏优先保留类型、摘要和状态，详情中的字段不丢失。Token 和模型默认在请求分组、概览与详情展示，避免每条用户输入或工具行都有无意义的空列。

一个请求可以产生 AI 说明、reasoning、多个工具调用，也可能失败而没有 AI 正文。保留可单独选择的请求分组，不能以“有没有 AI 回复”判断请求是否存在。

一个业务对象只形成一条稳定记录：文本 delta 更新同一条 AI 记录，工具中间输出更新同一个调用；不把每个 chunk 平铺成一行。原始增量保留在详情的事件序列中。重试是新的请求，子工具是独立调用，不能合并掉。

## 3. 通用列表字段与详情头部

| 展示项 | 建议数据字段 | 规则 |
|---|---|---|
| 类型 | `kind` | 用户输入、AI 回复、工具、审批等中文标签；同时保留稳定内部类型 |
| 摘要 | `title`、`preview`、`result_preview` | 单行显示；工具可展示“参数摘要 → 结果摘要”；完整值在详情 |
| 状态 | `status`、`status_reason` | 按对象生命周期定义，不能统一简化为完成/失败 |
| 位置 | `turn_id`、`run_id`、`step_id`、`request_id` | 界面用易读编号；ID 在高级信息中可复制 |
| Agent | `agent_id`、`agent_name`、`parent_agent_id` | 区分主 Agent 和子 Agent，父子关系可跳转 |
| 所属关系 | `parent_call_id`、`source_session_id`、关联记录 ID | 子会话活动仍在原父会话轨迹中查看 |
| 起点与耗时 | `started_at`、`duration_ms` | 时点事件显示发生/接收时间；没有持续时间则显示“—” |
| 记录范围 | `start_seq`、`end_seq`、`as_of_seq` | 序号 API 使用字符串；未终结对象没有最终 end_seq |
| 高级信息 | `record_id`、`event_id`、`message_id`、`part_id`、版本 | 放在概述的可展开区域，支持复制和关联定位 |

目标用户身份在会话信息中持续显示，不在每条执行记录重复展示。所有详情使用平台超管读取权限并校验目标 user/session 归属；“原始内容”页签不会绕过字段白名单去读取 provider 私有字段。

查看者 `viewer_id` 与目标用户 `owner_user_id` 分开。Query key、流式状态和详情请求包含查看者与目标会话身份；切换目标时取消旧请求/订阅并更新绑定 generation，迟到结果不能覆盖新页面。退出登录、停用或降为普通用户后清除相应缓存并关闭监控连接。

详情头部示例：`工具 · bash · 已完成`，面包屑为 `主 Agent › Turn 1 › Run 1 › Step 2 › Request 3`。并发层级来自持久关联 ID，不能按“上一条记录”猜父节点。

## 4. 各类记录的详情规格

以下为 OpenBox 的目标展示。字段名是接口设计建议，M0 固化到协议和读模型；本节不表示现有 Message/Part 已经保存了全部字段。

### 4.1 USER：用户输入

页签：**概述 / 内容预览 / 原始内容 / 来源**。

| 页签 | 详细字段 |
|---|---|
| 概述 | 输入摘要、接受状态、接收时间 `accepted_at`、注入模型上下文时间 `injected_at`（有记录时）、附件数量、关联 Turn/消息 |
| 内容预览 | 完整正文、Markdown、图片与附件卡片；附件名称、媒体类型、大小、历史版本、可用性 |
| 原始内容 | 提交时的内容块及顺序、文本原文、附件版本引用；保留多模态块，不拼成一段丢失结构的文本 |
| 来源 | `source_kind`、`actor`、`client_channel`、`message_id`、关联问答/恢复事件；例如 Web、移动端、API |

输入状态区分“已接受，等待注入”“已进入上下文”“被取消/替代”；接受输入不等于模型已经读到。发生在运行过程中的用户补充也保存具体注入位置。

只记录正式进入后端的输入和已保存草稿。输入内容页不自动包含模型使用的完整历史；完整历史属于模型请求的输入快照。用户输入没有“生成耗时”。

### 4.2 ASSISTANT：AI 回复与过程说明

页签：**概述 / 内容预览 / 原始内容 / 来源**。计时、选项与完整 usage 链接到对应模型请求。

| 页签 | 详细字段 |
|---|---|
| 概述 | 状态、`channel=commentary/final`、所属 Agent、对应请求、正文摘要、是否只有工具调用、调用数量、输出是否中断 |
| 内容预览 | 正文 Markdown、返回的 reasoning 折叠块、图片/其他产物、可点击的工具调用卡片；区分“过程说明”和“最终回复” |
| 原始内容 | 原始内容块的类型、索引、顺序、文本、工具名称/调用 ID/原始参数；支持查看当前位置之前的增量事件 |
| 来源 | 关联 `request_id`、`message_id`、`part_id`、模型、Agent、内容来源事件范围 |

状态区分“生成中”“已完成”“已中断”“生成失败”；中断后保留已捕获前缀。没有正文但产生工具调用时显示“仅工具调用”，不能当成空回复丢掉。

仅展示 provider 实际返回并已保存的 reasoning，没有返回时不生成推理内容。输出 token 可以在概述展示，但其值引用请求用量，不创建第二份计数。现有 [TextPart](../backend/models/message.py) 已有 `commentary/final` 通道，可作为展示依据。

### 4.3 REQUEST：模型请求

页签：**概述 / 输入 / 选项 / 用量 / 计时**。这是比 Harness 当前 Request 检查器更完整的 OpenBox 目标，增加请求实际输入快照。

| 页签 | 详细字段 |
|---|---|
| 概述 | `request_id`、provider、model、用途 `purpose`、状态、尝试序号、结束原因、错误码/错误信息、产生的 AI 消息/工具链接、前后重试/路由回退链接 |
| 输入 | 生效的 system/developer 内容、完整有序消息、附件历史版本、工具目录与定义、压缩后的实际上下文、`capture_level`、被省略内容及原因 |
| 选项 | 当次生效的 model/provider、stream、temperature、top_p、输出 token 上限、stop、thinking/reasoning 设置、tool_choice、parallel_tool_calls、response_format；只展示实际适用并捕获的参数 |
| 用量 | 输入 token 总数、缓存读取/写入及其他输入、输出总数、reasoning 子项；本次请求与截止当前位置的会话累计；usage 来源与完整性 |
| 计时 | 派发时间、首输出时间、首正文时间、结束时间、总请求耗时、首输出等待、生成耗时、输出速度、计时来源 |

辅助请求也必须出现，使用用途标签区分正文、压缩、标题、建议、工具内部分析和定时任务摘要。没有最终 Assistant 消息的失败请求、后台请求仍可打开检查。

“输入”提供结构化视图与捕获层原文，明确 `adapter_input` 和 `provider_wire`。用户原始一句话、模型实际 messages、工具参数是三个不同对象，不能共用一个含义不清的“输入”字段。

不同 provider 的 token 口径由后端规范化：缓存是否已包含在 input 中、reasoning 是否已包含在 output 中必须明确；不能直接套用相加公式。正文 token 只有在 provider 定义支持计算时才展示。费用若展示，应读取既有计费账本并标明未结算/已结算，不按当前价格倒算历史账单。

### 4.4 TOOL / SUBTOOL：工具调用与嵌套调用

基础页签固定为截图对应的 **概述 / 参数 / 结果 / Schema / 计时**。

| 页签 | 详细字段 |
|---|---|
| 概述 | 工具名与可读标题、调用 ID、状态、父请求/AI 消息/父工具、执行 Agent、原始参数摘要、实际参数摘要、结果摘要、错误/拒绝原因、产物数量、子调用数量 |
| 参数 | 模型生成的 `arguments_raw`、解析后的 `requested_arguments`、权限批准或修订后的 `effective_arguments`；发生修订时显示前后差异及对应审批 |
| 结果 | 已捕获的完整返回内容、中间输出、错误、公开 metadata、交给模型的裁剪/摘要结果及其来源；支持 JSON、文本、图片和产物卡片 |
| Schema | 工具 `name`、`description`、调用时参数 JSON Schema、来源与版本/digest；有返回定义时才显示结果 Schema |
| 计时 | 请求执行时间、授权等待、排队等待（有观测时）、真实开始/结束、执行耗时、总等待与执行区间、计时来源 |

Schema 树按原定义显示 `properties`、`required`、`type`、`description`、`enum`、`default`、数组/嵌套约束和组合类型，不从一次调用的参数值反推定义。优先展示模型当时看到的 Schema；batch 子工具若只能取得执行器注册定义，应明确标记来源 `executor_registry`，不能称作模型见过的定义。

工具参数流尚未构成完整 JSON 时，展示原始字符串与“参数生成中”，不填 `{}` 假装参数已完成。工具输出若是累积全文，按 replace 语义更新，不能重复追加。

建议状态：参数生成中、待授权、待执行、执行中、等待用户、成功、失败、拒绝、取消、超时、结果未知。拒绝发生在执行前时仍有调用记录，但没有实际执行开始时间和执行耗时。

子工具使用同一检查器，增加父工具链接和层级路径。工具名或 provider 原始 call ID 不承担全局唯一身份。

#### 按工具能力提供专用结果呈现

| 工具能力 | 参数/结果中的额外展示 | 约束 |
|---|---|---|
| 终端/命令 | command、工作目录、timeout；stdout/stderr、exit_code、信号、输出是否截断 | 运行时若只给合并输出，就展示合并输出，不伪造 stdout/stderr 分离 |
| 文件读取/修改 | 路径、读取范围；修改前后版本、diff、增删行数、历史文件链接 | 读取历史版本，不用沙箱当前文件替代 |
| 搜索/浏览器 | query/URL/action；结果条目、页面内容、引用、截图、导航结果 | 请求目标与实际返回目标分别保存；只显示已捕获项 |
| computer/远程桌面 | action、参数、目标、batch 原子动作列表；截图和子动作结果 | 没有录屏时展示已捕获截图，不能宣称连续录像 |
| 图像/音频/视频 | 输入素材、生成/处理参数；可预览媒体、尺寸/时长、版本、关联作业 | 作业等待和最终产物分开，不生成虚构中间帧 |
| 子 Agent 委派 | 任务、目标 Agent、运行方式；子运行链接、进度、返回结果 | 完整子执行树见 AGENT 记录 |
| MCP/插件/其他工具 | 当次 schema、结构化参数、原始返回块、公开 metadata | 未提供专用组件时仍能完整查看 JSON/文本/内容块 |

### 4.5 SYSTEM / CONTEXT：系统状态与上下文注入

| 类型 | 页签 | 详细字段 |
|---|---|---|
| 初始系统/工具状态 | 系统提示词 / 工具目录 / 来源 | 当时生效的完整系统内容、完整工具名称/描述/参数定义、对应请求 |
| 系统/工具状态更新 | 差异 / 系统提示词 / 工具目录 / 来源 | 更新前后引用、文本 diff、新增/移除/修改的工具、变化原因、生效请求 |
| 上下文注入 | 概述 / 内容预览 / 原始内容 / 来源 | 注入正文、角色、内容块、来源插件/技能/后台任务、注入时间与消费请求 |

工具目录包含未被调用但当时对模型可见的工具。技能正文、规则和后台结果等注入不能只显示“加载成功”，必须能检查实际进入上下文的内容或其不可变引用。

系统状态只在接入或变化时形成独立记录；每个 Request 的输入仍可以查看该次完整快照。相同 system 不在列表里为每个 chunk 重复插入。

### 4.6 AGENT：子 Agent 执行

页签：**概述 / 任务输入 / 执行树 / 返回结果 / 用量 / 计时**。

| 页签 | 详细字段 |
|---|---|
| 概述 | Agent 名称/类型、状态、父 Agent、委派工具、运行方式、实际子会话、所属父会话 |
| 任务输入 | 委派提示词、附件、约束、传递的上下文引用、子 Agent 生效配置 |
| 执行树 | 子 Run/Step/Request、AI 回复、工具、嵌套子 Agent、人机交互；支持进一步筛选/跳转 |
| 返回结果 | 返回父 Agent 的原始内容、父 Agent 实际收到的内容、产物、失败/取消原因 |
| 用量 | 本 Agent 直接请求与包含后代的汇总分别展示，均按 request_id 去重 |
| 计时 | 委派、开始、完成、等待与实际运行区间；并行区间不相加当总耗时 |

委派工具和子 Agent 是两个关联视角：工具记录解释调用输入输出，Agent 记录解释内部执行过程。会话统计不把二者的同一请求或同一段时间重复计算。

### 4.7 PERMISSION / QUESTION：审批与问答

| 类型 | 页签 | 详细字段 |
|---|---|---|
| 权限审批 | 概述 / 请求 / 决定 / 计时 | 关联调用、待审批操作和参数、审批原因、自动策略/用户决定、允许/拒绝/修订/过期、修订参数、决定来源、发起/决定时间和等待时长 |
| 用户问答 | 概述 / 问题 / 回答 / 来源 / 计时 | 完整问题、选项、选择模式、关联任务、已保存草稿、正式选项/文字回答、拒绝/取消、回答来源、提出/回答时间、恢复 Run |

问题本身、已保存草稿和最终回答分别标记；仅已保存草稿可按 seq 查看，不记录浏览器未提交打字。审批被修订时，可从决定跳到工具的实际执行参数。

轨迹详情始终是超管记录查看器。“待审批”“待回答”只展示目标会话的状态；实时与回放都不出现执行批准、提交答案或替用户操作的入口。关联导航只跳到轨迹中的问题、决定、工具和恢复记录。

### 4.8 INTERRUPT / RESUME / RETRY：中断、恢复继续与重试

这里将“AI 回复”和“AI 恢复继续”分开：回复是生成内容；恢复是执行生命周期的变化。

| 类型 | 页签 | 详细字段 |
|---|---|---|
| 中断/取消 | 概述 / 原因与影响 / 关联记录 / 计时 | 触发来源、取消/抢占原因、旧 run_id、最后已提交 seq、受影响请求/调用、保留的输出前缀、仍未知的外部结果 |
| 恢复继续 | 概述 / 恢复输入 / 关联记录 / 计时 | 恢复原因、原 run_id、新 run_id、沿用的 turn_id、触发的用户输入/问答/审批、恢复时有效上下文引用、恢复位置、开始时间 |
| 请求重试/回退 | 概述 / 尝试对照 / 错误 / 计时 | 原/新 request_id、attempt/max_attempts、错误码、计划等待、原/新 provider/model、实际输入/选项是否变化、各次用量链接 |

恢复记录由实际恢复事件和 `run.started` 中的 `resume_of_run_id`、触发事件关联投影生成，不按文本里有没有“继续”推断。新输入开启新任务时展示新 Turn；同一任务暂停后的续跑可沿用原 Turn。

请求重试不覆盖失败尝试。恢复与回放是不同操作：回放页面查看一条“已恢复”记录不会启动新 Run。

### 4.9 COMPACTION：上下文压缩

页签：**概述 / 压缩输入 / 摘要与原始输出 / 替换差异 / 用量 / 计时**。

展示触发原因（自动/手动）、范围、保留边界、使用模型、压缩请求、生成摘要、原始返回、成功/失败/取消、替换前后有效上下文引用。只有实际应用替换后才显示“已生效”，生成摘要成功与上下文替换成功分开表示。

前后 token 数、节省量和比例仅在捕获了可比较口径时展示；估算值注明估算来源。压缩请求费用与 token 来自关联 Request，不作为第二次请求累计。

### 4.10 JOB / ARTIFACT：后台任务与产物

| 类型 | 页签 | 详细字段 |
|---|---|---|
| 后台任务 | 概述 / 提交输入 / 进度与回调 / 结果 / 计时 | 作业 ID/类型、归属调用、提交参数、队列/外部作业身份、阶段进度、已观测回调序号、重试/取消、最终结果、提交/开始/完成时间 |
| 文件/媒体产物 | 概述 / 预览 / 版本或差异 / 来源 | 名称、类型、大小、尺寸/时长、摘要、版本、来源调用/作业、角色（输入/中间/最终）、生成时间、可用性、受控下载 |

回调在父 Run 结束后到达，仍展示在原会话并关联原作业。只有最终通知的远程系统展示等待与终态，不补造进度百分比。已删除或未保留内容明确标记；同名新文件不能覆盖历史预览。

### 4.11 状态变更、会话操作与记录边界

| 类型 | 主要展示内容 |
|---|---|
| PLAN / TODO | 结构化条目、顺序、状态、前后差异、变更原因、来源工具/Agent |
| SKILL / TOOL CATALOG | 加载名称、版本/内容摘要、可检查的实际内容、加载结果、生效范围与请求 |
| TAKEOVER 用户接管 | 接管原因、目标、请求/开始/结束状态、可观察交接内容、恢复关联；不自动录制用户所有键盘操作 |
| SETTINGS / REVERT / REGENERATE / FORK | 变化前后配置或上下文引用、操作来源、原/新分支、被替换的当前历史、产生的新 Run；历史执行记录继续可查 |
| BASELINE 记录开始 | 开始时间、旧会话标记、有效历史/配置引用、未完成交互快照、第一条新活动 |
| GAP / LATE RESULT | 缺口范围及原因、最后已知位置、补到的结果、原调用及原终态；未知字段保持未知 |

上述对象使用“概述 + 内容/差异 + 来源”，有真实持续区间时增加计时。工具调用引起的状态变化通过关联链接展开，默认挂在该调用下；不会将一次工具执行同时算作两次调用。

## 5. 计时、缺失字段与页签规则

### 5.1 计时展示

沿用主计划的指标口径。工具详情保留截图中的开始时间、执行时长、计时来源，并在存在记录时增加结束时间、授权等待和排队等待。模型请求单独展示首输出等待与生成时长，不能使用包含工具执行的 Step duration 代替请求耗时。

- 日期显示本地时区和毫秒，支持查看 UTC/Unix；明确时区，不混用无说明的客户端时间。
- 时长显示毫秒或秒；tooltip/详情可查看精确值。
- `timing_source` 区分生产者单调时钟、已记录会话时间戳差、运行中视图估计；不一律写“Session timestamps”。
- 正在运行的计时明确标记动态估计；回放时按播放位置对应的记录时间计算，不能随现实时间继续增长。
- 用户输入、恢复起点、文件生成等时点不拉成虚假执行条；等待区间单独画，缺失时间不填 0。
- 工具、子 Agent 和请求允许重叠，总墙钟时间使用生命周期区间；统计不简单相加。

### 5.2 内容可用性

| 情况 | 展示 | 禁止的替代值 |
|---|---|---|
| 当前播放位置尚未发生 | 尚未产生/等待中 | 最新最终答案或最新产物 |
| 适用但未捕获 | 未记录，并注明原因/捕获层级 | `0`、空对象、假成功 |
| 类型不适用 | 不显示该指标，必要时使用“—” | 工具的模型 token、用户输入的生成速度 |
| 确认完成且为空 | 无输出/空结果 | 未记录 |
| 内容已删除/过期未保留 | 已删除/不可用 | 同名当前文件或新签名指向的不同版本 |
| 内容损坏/协议不支持 | 明确错误和受影响范围 | 静默跳过后宣称完整回放 |

建议详情字段/分区携带 `availability` 和 `reason`，区分 `available / pending / not_recorded / not_applicable / deleted / unsupported / corrupt`。这是展示读模型字段，不覆盖原始事件事实。

### 5.3 页签与内容操作

页签由记录类型决定。工具的五个基础页签在整个生命周期保持位置稳定：运行中 Result 展示等待，未捕获 Schema 展示原因。可选能力页签只有确实不适用时隐藏，不因结果尚未到达而反复出现/消失。

长文本、JSON 树和媒体按需加载；支持复制正文、JSON 值/路径/整体、记录链接和查看所属请求。预览截短不等于保存内容截短，详情应能读取已保存的完整值。原始值与渲染预览分开，不自动执行内容中的命令、脚本或交互指令。

## 6. 回放时所有区域使用同一位置

列表、详情、请求输入/输出、计时、用量累计、Agent 树、文件预览都使用同一 `as_of_seq`。即使同一条工具的最新状态已经成功，跳回开始时也只显示当时参数和运行状态；不能从最新详情接口补来未来结果。

实时最新水位和超管播放位置分开。回放时右上可提示“实时又有新活动”，但不改当前选中记录和播放位置。“回到实时”才把展示推进到最新已提交水位。

当前超管权限撤销和显式内容删除仍然生效：即使回放到删除前，也不能绕过当前权限读取已经删除的内容；界面显示不可用原因。媒体预览、原始内容读取、导出状态和下载均走受控的超管接口，不能回落到目标用户的普通附件 API 或公开分享链接。

搜索默认限定当前查看范围；需要搜索播放位置之后的实时内容时必须明确切换范围。定位尚未到达的结果需要先改变播放位置，不能直接在当前历史状态展开未来正文。

任意用户的旧会话续聊后，在超管详情的首次记录处显示“从此处开始记录”。历史消息只在基线或新请求输入中出现；列表和统计不补造上线前的用户输入、模型请求或工具步骤。普通聊天页面不展示轨迹入口，采集不依赖超管打开详情。

## 7. 实施与界面验收

M0 固化平台超管权限、跨用户列表查询范围、类型到页签的映射、每个字段的生产来源、单位、可用性和快照水位。前端类型从统一协议/读模型生成或验证，不能靠 UI 字段名临时猜测后端 Part。

M6 实现超管栏目、跨用户列表、详情路由和分类型检查器；M7 覆盖权限、返回列表恢复以及同一详情在运行中、完成、失败和历史位置的差异。复用 shared 的表格/JSON/Markdown/媒体组件，检查器不导入工具执行或审批提交处理器。

在主计划 AC01–AC37 基础上，补充以下展示验收：

| 编号 | 场景 | 预期 |
|---|---|---|
| UI01 | 同一请求依次选中用户、Assistant、工具、Request | 页签与字段各自正确；三种“输入”含义清楚 |
| UI02 | 工具从参数生成到审批再到成功 | 五个页签位置稳定，原始/实际参数与修订关系可见 |
| UI03 | Assistant 只有 reasoning 或只有工具调用 | 不显示为空回复；可检查实际返回块并跳到调用 |
| UI04 | 请求失败、重试、切换 provider | 每次尝试可独立打开，错误、选项、输入、usage 不被覆盖 |
| UI05 | batch 和多层子 Agent | 可跳转父子树，Schema 来源准确，统计不重复 |
| UI06 | 问答/审批结束后恢复 | 问题、回答、旧/新 Run 关联清楚，回放没有提交按钮 |
| UI07 | 回放到工具结果/文件产生之前 | 结果、媒体、计时和累计统计均不泄露后续状态 |
| UI08 | 未记录、空结果、删除、未知结果 | 使用不同文案和状态，不统一显示为 0 或空白 |
| UI09 | system/tools 改变或上下文压缩 | 能查看当时完整值、前后差异和生效请求 |
| UI10 | 旧会话首次续聊 | 显示记录起点，新请求里可查实际旧上下文，无历史步骤补造 |
| UI11 | 长 JSON、长输出、多模态、窄屏、深色主题 | 内容可完整检查，类型与层级可识别，页签可键盘访问 |
| UI12 | 后台终态晚到，正在历史回放 | live head 前进，历史选择和 playhead 保持不变 |
| UI13 | 普通用户、会话所有者、仅工作区管理员 | 无轨迹入口，直达列表/详情无数据；超管可打开全部目标会话 |
| UI14 | 超管筛选用户/工作区、翻页、进入详情再返回 | 列表与目标对应，返回保留筛选和位置；查看未记录会话不初始化日志 |
| UI15 | 跨用户快速切换、退出登录、超管降权 | 目标身份始终清楚，旧响应不串线，缓存/订阅被清理，已创建导出也不能继续读取 |
| UI16 | 超管只查看正在等待审批的其他用户会话 | 无代发消息、批准、回答、取消、创建沙箱或继续执行；审计与原执行日志分离 |

完成标准是平台超管可以从跨用户列表进入任意已记录会话，每一类已捕获业务事实都有明确的展示位置、可检查的详情与历史状态，普通用户没有轨迹读取权；新增事件类型必须同时补齐本规格中的展示映射和验收样例。
