## 1. 如何理解表里的标记

| 标记 | 含义 | 是否直接限制说话 |
| --- | --- | --- |
| **固定播报** | 指定完整句子，并要求“只说这一句” | 提示模型照读，未发现输出必须逐字相同的程序校验 |
| **表达规则** | 指定称呼、长度、语气、顺序等 | 模型提示层面的限制 |
| **程序匹配** | 正则或词表匹配用户／助手的文字 | 可能直接改变静音、交办、答卡等流程 |
| **事实模板** | 把真实结果包装成后台资料 | 供模型转述，通常不要求照读模板 |
| **卡片文案** | 显示操作、影响、选项或答卡错误 | 模型读到后可能口头解释；部分选项需精确匹配 |
| **内部提示** | 给摘要、规划、路由、保活使用 | 不应直接对用户朗读 |
| **界面文案** | 按钮、状态、设置说明 | 单独显示它不会触发语音播报 |

## 2. 固定播报、兜底句：什么情况下说

| 词句原文 | 类型 | 触发情况 |
| --- | --- | --- |
| 办好了，结果我写在对话里了。 | 固定播报／兜底 | 助理成功结束但清洗后无可读答复且无确认卡，或结果播报被拒绝并放弃继续播报 |
| 这通电话到时间了，我们文字里继续。 | 固定播报／兜底 | 当前通话达到时长上限，准备结束 |
| 积分用完了，这通电话先到这里，充值后可以接着打。 | 固定播报／兜底 | 通话中积分耗尽，准备结束 |
| 刚才线路断了一下，您再说一遍？ | 固定播报／兜底 | 连接恢复成功且刚才用户说话或助手回复被断线打断，需要重说 |
| 这件事还在办，办好了我在对话里告诉您。 | 兜底事实文本 | 等待助理本轮结果超过配置的超时，原任务可能继续 |
| 刚才没办成，原因我写在对话里了。 | 兜底事实文本 | 已接收的助理轮次失败、等待异常或卡片续办失败 |
| 我这边没能交给个人助理，您稍后再说一次吧。 | 兜底事实文本 | 请求尚未被助理接收就发生交接异常 |
| 详细的我写在对话里了。 | 长度截断补句 | 助理结果／报告清洗后超过 clean() 的 limit；默认 300 字符 |

这里有一个细节：**“办好了，结果我写在对话里了。”既可能用于成功但没有可读答复的情况，也可能用于结果播报被拒绝后的兜底。** 这个句子的触发本身不能证明底层任务已完成。

固定播报入口会拼上：**“只说这一句，不要调用任何工具，不要加别的话：”**。超时／失败三句通常先变为备注，再由模型用自己的话转述。最后的长文本补句是默认约 300 字符截断后的补句；不是直接限制每轮自由聊天为 300 字。

触发逻辑：[助理结果处理](/Volumes/fanxiang/workspace2/OpenBox/backend/voice/assistant_link.py:184)、[放弃结果播报后的兜底](/Volumes/fanxiang/workspace2/OpenBox/backend/voice/turns.py:898)、[通话限额](/Volumes/fanxiang/workspace2/OpenBox/backend/voice/bridge.py:446)、[重连通知](/Volumes/fanxiang/workspace2/OpenBox/backend/voice/bridge.py:748)。

## 4. 按场景追加的长度、用词和动作要求

| 确认卡 | 要用户先决定，才可执行 | 说明做什么和影响，再问“确认吗”；本轮不能代选或调用工具 |

## 5. 用户输入关键词：哪些会改变流程

下面词表不是“用户不能说”的词。它们用于判断意图、控制静音、决定是否答卡或交办。

### 5.1 静音与恢复

| 词句／组合 | 什么时候检查 | 命中后发生什么 |
| --- | --- | --- |
| 闭嘴、住嘴、闭上嘴、闭上你的嘴 | 每次收到用户最终识别文本 | 进入 `hushed` 静音 |
| 别／不要／甭／先别／先不要 + 可选“再” + 说／讲／念／吵／叨叨／啰嗦／出声／吭声 + 了／啦／话 | 同上；按正则组合匹配 | 同上 |
| 别／不要／先别／先不要 + 可选“再” + 吵／出声／播报 | 后接句末、标点或空白时 | 同上 |
| 停止播报 | 最终识别文本出现此片段 | 同上 |
| 你／您 + 可选“也” + 太 + 聒噪／吵／啰嗦 + 了 | 同上 | 同上 |
| 太聒噪了 | 作为整句，可带正则允许的语气和标点 | 同上 |
| 先别说、别打扰、不要打扰、别烦我、保持安静、少说两句 | 识别文本出现此片段 | 同上 |
| 可选“你／您”、可选“先” + 安静点／一点／一下／一会儿／一会／会儿／些 | 按正则组合匹配 | 同上 |
| 安静 | 作为整句，可带“你／您／先”和正则允许的语气标点 | 同上 |
| 非上述静音表达，且不全是填充语的新发言 | 已经静音之后 | 解除静音，恢复模型回应和待播结果 |
| 嗯、那个、就是等纯填充语 | 已经静音之后 | 保持静音 |

静音会清除客户端待播放音频、取消当前普通模型响应、丢弃静音期间的后续音频；待播结果保留。正则不是完整语义理解器；不少分支是查找子串，引用或复述这些词时也需要注意匹配范围。完整正则见附录，以上组合不是另一套规则。

程序还有上下文条件：必须是当前卡片、用户在读卡后真实说过话、选择属于原选项。普通非取消回答距离读卡超过 **2 次用户发言**时要求重读卡片。**刚读完卡片后的第一句明确拒绝，可由程序直接提交“取消／不用记”**；不是每次聊天说“算了”都取消某张卡。

“好的”在普通确认卡中可能算同意，但不能替用户选择“新对话”还是“新项目”。位置卡只接受唯一选项匹配。短回答路由有 **8 字符**条件，但位置卡另有完整选项匹配路径。

## 13. 容易混淆的地方

- **“稍等／等一下”不是全局禁用播报词。** 它们在确认匹配里代表犹豫或等待，阻止把整句当作明确同意。
- **“闭嘴”不是违规处罚词。** 当前代码用它识别停播要求，并直接控制播放。
- **“付款／病／政治”等不是聊天禁词。** 前者影响高风险代答确认，后者属于拟保存记忆的敏感词匹配。
- **“好嘞，我闭嘴”“我这边查到了”“对了，跟你说一下”“等下，我刚才说错了”目前只在相关历史注释里出现。** 不把它们算成现行固定播报指令。
- **代码里的“自然说话”说明不代表没有模板。** 当前任务卡提示仍有具体视频示例，主助理也仍有多组示例。
- **“你”与“您／老板”来自不同层。** 主助理和实时前台要求不一致；设置页“留空就不加称呼”与前台默认“老板”也不一致。
- **除了中文还有英文限制。** 主助理语音回合默认两三句、详细时四五句；实时前台详细偏好则写三四句。这些英文原文已附在附录末尾。
