# 语音助手与口播视频任务

## 模型与任务创建

- 主助手读取真实配置的任务 AI 和视频模型，结合上下文解释选项。
- 新任务会话创建前完成任务 AI 选择。视频需求先确认是否口播，再选择视频模型。
- 用户明确选择或委托系统决定时沿用，不重复询问。账户默认值本身不视为本次选择。
- 未完成选择只保存问题卡；取消不创建项目、会话或任务。重复回调复用同一任务。
- 口播任务带入已有 `video-production` 技能、所选模型、分辨率和完整需求。
- 意图理解由模型完成；服务端验证配置 ID、归属、版本和提交状态，不匹配中文指令关键词。

## 语音接管任务卡

- 语音可读取完整问题、选项说明、当前任务的稿件与方案，以及卡片草稿中已选的素材。
- 同一次回答提交全部问题和素材 ID；缺少答案时先澄清，不填默认值。
- 用户在卡片上上传的图片可直接被语音识别，无需重新听写文件名。
- 上传草稿不是确认。使用图片、参考生成新图、视频生成费用仍按当前问题和用户决定处理。
- 校验实际发言、卡片版本、任务归属、图片归属及人工接管限制。问题或素材变动后重新读取。
- 语音询问图片内容时读取真实图片；不依据名称编造描述。
- `decision_recorded` 表示回答已提交，不能当作视频已完成。
- Audio 3.1 的附件 JSON 字符串在入口解析为数组；原卡片的问题数量、素材归属和版本校验不变。多道素材题不会猜测图片应分配给哪道题。
- 提交卡片的同一轮语音先等待真实工具回执；同一次发言最多校正一次参数，持续失败停止自动调用，不循环提交。

## 图片通道与技能流程

- Web 和移动端设置提供 **Default / RunningHub**，选择按用户保存。
- RunningHub 具体图片模型由服务端 `image_generation.runninghub_model` 统一配置；密钥留在服务端。
- 技能保留讲稿、素材、完整分镜及费用、实际音频转写和最终交付检查。
- 首尾帧能力按所选视频模型读取。帧率与首尾帧是不同概念；实际时长和 FPS 由成片测量。
- 内置技能资料的执行路径是 `/opt/openbox/skills/<name>/`；自定义主机技能不会因此取得沙箱文件可访问声明。
- 网络错误在尚未产生模型输出时使用已有有限重试预算；已产生输出的请求不自动重放。

## Wan 3.0 原生阿里云通道

服务端可将现有 Wan 模型绑定到 `dashscope` 通道。不会自动改动已部署的中转配置，也不会将旧任务 ID 发往新账户或新地址。

```json
{
  "provider": {
    "aliyun-video": {
      "api_key": "{env:DASHSCOPE_API_KEY}",
      "base_url": "https://dashscope.aliyuncs.com"
    }
  }
}
```

在现有 `video_generation.models` 中，将目标 Wan 条目的 `channel` 设为 `dashscope`、`provider` 设为 `aliyun-video`；保留其模型 ID、时长、分辨率和能力声明。也可使用对应地域的工作空间域名，密钥和地址必须属于同一地域。以上是配置片段，不能覆盖整个模型清单。

适配器发送原生 `input.media` 和 `parameters`，保留首帧、尾帧及参考素材的用途，并关闭额外提示词改写。首尾帧不能与参考图像/视频/音频混用；不合法组合在付费提交前拒绝。提交后保存 `output.task_id`，只查询原任务并将成片保存到资源库。查询过期或服务返回异步校验失败时明确报告，不能自动新建一条替代任务。

协议及限制依据：[阿里云 Wan 3.0 API](https://help.aliyun.com/zh/model-studio/wan3-video-generation-api-reference)、[千问 Wan 3.0 模型页](https://www.qianwenai.com/models/wan3.0-video)。

## 验收范围

仅执行与本次变更相关的后端测试、问题卡前端测试、TypeScript 检查和移动端改动文件分析，没有执行全量测试。
浏览器验收使用本地 QA 账户，从助手入口创建任务、设置图片来源、回答问题卡、上传图片和播放实际视频。
语音验收通过浏览器麦克风输入测试音频，连接真实 Audio 3.1 服务；不等同于物理麦克风声学测试。

原始日志、测试音频、账号信息和截图保存在本地验收目录，不提交到仓库。

协议参考：[阿里云 Qwen-Audio 客户端事件](https://help.aliyun.com/zh/model-studio/fun-audiochat-client-events)。

### 本地实测结果（2026-10-12）

| 场景 | 结果 |
| --- | --- |
| 新会话任务 AI、口播形式与视频模型选择 | 浏览器验证先询问、解释疑问，再创建；保留已明确的选择 |
| RunningHub 图片与图片内容解释 | 实际生成咖啡师首帧；语音调用视觉读取图片后解释 |
| MiniMax-H3-Max-Turbo | 完成讲稿、首帧、费用、转写和交付；浏览器可播放，实测 5.184 秒、480×832、24 fps，转写与原稿一致 |
| Wan 3.0 上传素材与语音接管 | 同一任务卡上传图片，真实 Audio 3.1 提交图片 ID 和用途，任务继续完成首帧与镜头费用确认 |
| Wan 3.0 实际成片 | 按用户要求复用本地语音服务的阿里云 Key，改用原生 DashScope 通道；浏览器确认本次费用后完成新样片，实测 5.039 秒、720×1280、30 fps，实际转写与原稿文字一致，已提交交付验收 |

旧中转网关那次连接中断的记录单独保留，未将其任务身份或受理结果伪装为阿里云新任务。新通道仅在本地配置启用，密钥通过环境变量读取；生产启用仍需相应的服务端配置与发布。

以上为单镜头 5 秒样片验收；不代表长视频拼接、多镜头一致性或移动端真机语音已完成实测。网络错误提示不再承诺尚未确定的任务会自动恢复。
