BIP-01反馈第 1 项 · App

素材库分类与跨类别一次确认

在素材库里快速找到某类文件。进入「生成」按原会话找 AI 产出。照片、视频和生成素材可以跨分类混选，一次带回制作页。

1 顶部直接切换常用分类2 分类只筛选当前列表3 底部汇总跨分类已选项4 在「生成」中按会话归档

现状与原因

资源中心已有类型筛选，入口收在「筛选」弹层内。制作选择器已有照片／视频分段与共享的 _selected，但从照片开始，没有混合视图，加载期间也无法切换分段。这两处的使用路径不同。

实现方案

  • 资源中心露出「全部／照片／视频／文件」，文件使用现有 document 分类，原有其他类型从「更多」进入。
  • 制作选择器默认「全部」，按任务允许的类型展示。视频任务可混选照片与视频，菜单和海报只展示图片。资源中心和制作选择器都提供「生成」，用原会话标题分组。子任务产出归到上层会话，无可读原会话的素材归到「未归档的生成」。
  • 沿用素材 ID 集合和 10 个上限。每类维护自己的页码与加载状态，快速切换时丢弃旧分类的过期响应。取消丢弃本轮改动，一次确认提交完整 ID 列表。

验收标准

  • 资源中心可直达照片、视频、文件，原项目和来源筛选仍可组合。
  • 选一张照片 → 切视频选一个 → 在「生成」选一项 → 返回照片仍有勾选 → 一次确认带回三件素材。同名会话分别成组。
  • 加载失败可重试，切换、分页和重新打开都能正确反映选中状态。混合列表先按允许类型过滤再分页。第 11 项给出上限提示，已选项仍可取消。

BIP-02反馈第 2 项 · Web / App

对话重命名与批量删除

在现有对话列表里找到单条操作，或者进入多选模式一次处理多条对话。

1 自有会话的「···」提供改名、删除2 列表进入多选模式3 确认框显示实际条数

现状与原因

Web 会话行悬停只显示删除，但已有改名 API 和 mutation。App 已能长按改名，入口藏在手势里。自动标题使用首条用户文本生成，失败时取首行节选。Web 侧栏和 App 专业模式的对话抽屉都缺少批量管理。简易模式的助理页仅承载固定助理，制作记录对应内容制作任务。

实现方案

  • Web 和 App 的自有行增加可点击、键盘可达的「···」。改名复用 PATCH 和标题事件，预填当前标题，拒绝全空白。自动标题只在标题仍为初始值时更新，以免覆盖手动改名。
  • 批量模式按会话 ID 记录当前工作区手动选中的会话。简易模式需要管理普通对话时，从「我的 → 对话记录」打开同一列表。共享给你的会话、固定个人助理不提供勾选。工作区切换时清空选择。
  • 批量接口逐条复用单条删除逻辑，一次最多确认 100 条。展示成功／失败数量，保留失败项供重试。当前会话成功删除后回工作区列表，刷新搜索结果和会话列表。

验收标准

  • Web、App 用同一账号互相看到新标题，首轮自动标题迟到时保留手动名称。
  • 勾选 2 条只删这 2 条。取消时不提交。部分失败有汇总并可重试。
  • 非自有会话无法被操作，固定助理保护与单删清理流程照常生效。

BIP-03反馈第 3 项 · App 助理

把待处理事项放回「我的任务」

反馈截图红框是「有 5 件事等你处理」的待处理卡。它当前占用对话末尾空间，消息越多时越容易把历史挤出当前视口。

1 顶栏待处理数量2 消息区域保持原滚动位置3 在任务面板回复或审批

现状与原因

AssistantScreen 在消息列尾部挂载 AssistantRequests。待处理结果异步刷新，整块卡片进出消息滚动区。任务面板已经能显示同一组件，顶栏也已有待处理数量。

实现方案

  • 移除简易和专业 App 助理页消息列尾部的聚合卡，复用「我的任务」按钮、红色待处理计数和现有任务面板。
  • 保留每条实际消息自身的互动和回复入口。通知直接打开对应待办时沿用现有定位。待办刷新只更新顶栏及已打开的面板。
  • 单独验证角色介绍和使用导览的自动打开时机。若复现已有历史时抢焦点，将自动展示限定在空会话，保留从设置手动打开。

验收标准

  • 正在阅读历史时，待处理从 0 增加到 5、再降为 0，消息滚动和输入焦点保持。
  • 点「我的任务」能找到并处理原先问题和审批，关闭面板后返回同一条消息。
  • 简易、专业两个入口和通知跳转各检查一次。已有历史时记录是否发生独立导览自动弹出。

BIP-04反馈第一个第 4 项 · App 做菜单

粘贴清单或识图，逐行确认菜名与价格

将已有文案或旧菜单上的菜品一次导入。在菜名左、价格右的同一行内核对，改完再写入制作草稿。

1 菜品区的批量导入2 粘贴或选图识别3 同一行核对，疑项高亮4 确认追加到草稿

现状与原因

首页「做菜单」进入制作表单。ProductionDishes 每次只能录入一行。图片识别已存在，在进入核对时触发 prepare，也可以在核对页重试。缺的是菜品资料页可主动启动的批量入口、文本导入和写入前独立预览。

实现方案

  • 粘贴先按整行和明确分隔符读菜名／价格，保留货币、分组符和单位。无法可靠配对就保留原文并标记待核对。
  • 图片复用当前识别能力，结果先写到导入候选，沿用当前草稿 revision 做并发检查。确认后才追加到 dishes，已有同名项标明冲突，由用户确认保留或更新。
  • 每行可编辑或删除，保留手工加菜和价格选填语义。受现有 30 道上限约束，超量时允许先删减候选。图片识别用本次选定的素材 ID，旧草稿仍按现有保存规则处理。已核对同一批图片后跳过进入核对页时的重复识别。

验收标准

  • 粘贴多行或选择旧菜单图，两条路径都出现可编辑预览，取消和识别失败时菜品列表保持原样。
  • ¥38/份、45.000 ₫ 与菜名正确对应。模糊价、同名菜和超量都可在确认前处理。
  • 确认后菜品页与核对页一致。回退、重复提交和识别晚回包都不会复制菜品或覆盖手改内容。

BIP-05反馈第二个第 4 项 · App 登录

新账号登录后直接进入简易首页

注册后的第一个业务画面使用现有简易首页。重新登录和换设备时按该账号已经选定的模式进入。

1 服务端确定账号默认值2 冷启动无缓存时先解析模式3 简易首页及导航为首屏验收点

现状与原因

密码注册和首次 Logto 建号都尝试写入 light，失败只记日志。若偏好接口成功返回但缺 ui_mode，客户端仍按 pro 处理。Logto 客户端的注册按钮也不能证明服务端刚创建账号。冷启动无账号缓存时，当前首屏同样先按 pro 选路由。模式加载完成前现在显示加载或重试状态，避免落到专业首页。

实现方案

  • 在服务端建号事务内初始化模式，认证响应返回有效模式。显式偏好优先，既有账号缺值按兼容策略解析。
  • 登录先把有效模式写到对应用户再触发路由。冷启动无缓存时用现有加载屏等待解析，无网络时沿用现有重试。有效缓存按账号隔离。
  • 曾走新账号流程且仍有首条视频邀请标记的账号，缺模式时按简易处理。显式专业偏好保持优先。

验收标准

  • 密码注册、Logto 注册入口、Logto 登录中首次建号三条路径均以简易模式进入。默认跳转显示简易首页，深链和首条视频引导按现有规则处理。
  • 偏好读失败、缺字段、冷启动无缓存、换账号均不会短暂打开专业工作台。
  • 既有专业偏好保留。切换模式、重新登录和换设备时读取同一账号的偏好。

BIP-06反馈第 5 项 · Web 超级管理后台

通过电话号码或邮箱定位账号

在超管使用单独的账号查询入口。运营选择查询方式，定位账户后查看账号信息和默认工作区。

1 新增「账号查询」导航项2 手机号／邮箱按对应规则查询3 展示脱敏结果和已有工作区入口

现状与原因

GET /api/admin/users 已按用户名、邮箱模糊匹配。当前超管导航没有账号入口。User 模型没有电话字段，现有 Logto 建号代码也未保存电话，所以仅增加搜索框无法按电话查到对应用户。

实现方案

  • 新增 Web 超管「账号查询」页，复用现有 DataTable、分页和表单。手机号按区号规范化后精确匹配，邮箱去空格并做大小写无关匹配。按搜索、重置、空结果、失败四种状态交付。
  • 沿用超管权限，在现有列表 API 增加结构化查询参数，兼容现有 q 的调用。结果回传脱敏联系信息，查询审计记类型、账号/结果数量等必要信息，避免记录明文联系方式。
  • 手机号从 Logto 的已验证声明同步，按带区号的规范号码精确查找。历史账号按 Logto 身份 ID 回填，手机号缺值显示空，搜索结果脱敏。

验收标准

  • 同一号码的带区号、带空格写法命中同一账号，邮箱大小写一致命中。
  • 空结果、重置、分页和接口失败都有状态。无号码或邮箱的账号显示空值。
  • 普通账号访问 UI 和接口均无权。结果和审计记录不暴露明文电话。
