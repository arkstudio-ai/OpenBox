# 文档维护规则

## 文档放哪里

根目录 README 介绍产品、结构和启动入口；每个子项目 README 说明自身职责、配置、命令和验证。
跨模块内容进入 `docs/`，分类见[文档首页](../README.md)。同一流程保留一个维护入口，其余位置通过链接引用。

| 内容 | 归属 |
|---|---|
| 现行职责与生命周期 | `architecture/` |
| 接口、协议、字段、工具清单 | `reference/` |
| 部署、配置、排障、恢复 | `operations/` |
| 开发与维护方法 | `contributing/` |
| 目标设计、阶段计划、执行单 | `plans/<topic>/` |
| 某次验证或发布的结果 | `reports/<topic>/`，文件名尽量包含日期 |
| 对比、选型与实验 | `research/`、`spikes/` |
| 退役、被替代或搁置设计 | `archive/` |

方案被实现后保留原决策，并链接实现记录；不能把“有方案”写成“已实现”。
操作手册不叠加无穷发布日志，发版结果另写日期记录并回链。

## 内容与链接

- 指明适用范围；历史材料中的版本、价格、路径和测试数量属于当时结果。
- 命令注明执行目录与前置依赖。核对仓库脚本，不把规划中的 CI 检查说成已启用。
- 仓库内使用相对链接；不提交个人机器绝对路径作为可点击来源。外部 checkout 的研究引用注明仓库与路径、已知提交，不伪造网络链接。
- 删除或移动文档时更新引用。此次迁移对应 [moved-documents.json](../moved-documents.json)，目标必须可用。
- 不收录忽略的私有文件、凭据或日志中的敏感内容。示例变量用明确占位。
- `SKILL.md` 的名称、安装位置和内容属于运行协议；普通目录整理不能改变其行为。
- 评测 `PROTOCOL.md`、用例和结果 JSON 可能被哈希引用，保留内容与路径。结果说明的导航链接可以维护，不改变实验数据。
- vendored 文档、许可证与上游变更日志保留来源，不为了统一风格改写上游历史。

## 检查

在仓库根目录执行，使用 Python 标准库，不需要安装文档框架：

```bash
python3 scripts/check_docs.py --write-index
python3 scripts/check_docs.py
python3 -m unittest discover -s scripts/tests -p 'test_*.py'
git diff --check
```

[检查脚本](../../scripts/check_docs.py)枚举 Git 管理和未被忽略的新文档，生成
[全仓目录](../CATALOG.md)，检查 Markdown 的本地文件链接、图片链接、标题锚点和迁移映射。
它忽略代码块中的链接示例，不访问远程 URL，不读取被忽略的私有文件，也不执行示例命令。
外部网站的内容和可用性、接口语义与环境现状仍需在相关开发或发布时核对。
