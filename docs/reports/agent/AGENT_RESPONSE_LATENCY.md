## 实测拆分

### 沙箱空闲后的延迟：main 同样存在

使用两版 `SandboxClient`，相同无影开发沙箱、相同隧道和连接复用选项，顺序调用 `/alive` 与无副作用的 `true` 命令。未修改远程服务。

| 请求条件 | main | 当前分支 |
| --- | ---: | ---: |
| 首次连接的 `/alive` | 3,313 ms | 3,626 ms |
| 连续复用的 `/alive` | 56–63 ms | 50–64 ms |
| 空闲 6 秒后的 `/alive` | 3,318–3,383 ms | 3,312–3,420 ms |
| 紧接上述请求执行 `true` | 84–180 ms | 91–170 ms |

连接空闲后的重新建立解释了实际对话中发送前、模型完成后各约 3.3 秒的等待。客户端连接池仍在，但无法阻止服务端或隧道关闭空闲连接。下一步应针对 Action Server 与隧道的空闲超时核实并调整；本次没有部署或重启远程共享沙箱。

### 重构新增开销：重复读取和重建完整历史

使用相同离线脚本运行 100 轮短对话，替换模型为立即返回的固定流，关闭沙箱、标题、建议和轨迹记录。每个版本使用独立的本地 PostgreSQL schema，保留真实 agent loop、事务和持久化。数据为第 91–100 轮中位数，包含诊断包装开销，属于本机对照值，不是生产吞吐承诺。

| 测量项 | main | 重构修复前 | 本次修复后 |
| --- | ---: | ---: | ---: |
| 提交消息至模型调用前 | 70 ms | 619 ms | 383 ms |
| 完整本地单轮处理 | 133 ms | 957 ms | 659 ms |
| 每轮完整事件历史读取次数 | 不适用 | 7 | 5 |

模型调用前的本地开销减少约 38%，完整本地单轮处理减少约 31%。SQLite 对照也从第 100 轮的约 802 ms 降至 526 ms。新增租约、事件记录及完整历史校验仍有成本，较长文本、更多工具与更多流式检查点可能进一步放大该成本。

本次代码修改：

- 数据加载层只读取事件，由调用方统一执行完整投影校验，消除紧接着重复执行的同一投影。
- 在同一个持有 Session 锁的事务内，恢复检查和模型投影共享已读取、校验过的事件前缀。
- 恢复若追加事件，则重新读取和验证；同时检查事件序号，覆盖只追加生命周期记录的情况。没有跨请求缓存或跳过并发、归属、序列完整性检查。
- 压缩历史时复用已覆盖消息 ID 的集合，避免为每条消息重复构造集合。

### 模型服务自身等待

现有日志中 Gemini 主请求首块约 4.9–6.0 秒，Qwen 主请求约 1.7–4.7 秒。
修复后的浏览器新会话实际回复“延迟回归通过”：Gemini 首字 6.68 秒、模型请求总时长 6.76 秒；结束后的快照另花约 3.4 秒。页面显示的 6.8 秒不包含提交前准备和后续快照的全部耗时。

标题使用的 Luna 在早先样本中耗时约 36–176 秒，本次浏览器样本约 28 秒。标题任务在后台运行，不能将其耗时算成主回复首字等待。本次没有降低推理强度或更改用户提供的模型配置。

第二轮已落地的本地改动：

1. 历史重放中的 JSON 标量先走常见类型路径，避免对每个字符串、每层字段反复做 `typing.Mapping` 检查。
2. 模型上下文重放与事件前缀摘要共享规范化结果；被压缩或排除的消息先筛选，再复制需要的内容，去掉重复深拷贝。
3. 较长历史的纯计算移出 ASGI 事件循环。数据库事务和锁仍由调用线程持有；被取消的计算无法提交恢复记录。
4. 保留旧版本摘要兼容性，新增固定摘要测试覆盖中文、emoji、真实 NUL、字面的 `\u0000`、大整数与浮点数。

为减少不同版本同时运行造成的竞争，重新串行运行相同的 PostgreSQL 离线基准。仍取 100 轮中的第 91–100 轮中位数，排除模型服务与沙箱等待。第一轮代码从本地快照恢复到独立目录后对照运行。

### 沙箱保活修复：源码已完成，远端未部署

只读检查确认，当前开发配置所用 `bossip-sh-008`（`ecd-4y9s9igraz7hc58ea`）的 Action Server 启动未设置 `timeout_keep_alive`，与默认 5 秒空闲超时一致。

仓库代码已将默认值设为 **75 秒**，同时支持环境变量 `ACTION_SERVER_KEEP_ALIVE_TIMEOUT` 和参数 `--timeout-keep-alive`。真实 Uvicorn HTTP 测试验证空闲 6 秒后仍使用同一 TCP 连接，相关连接池与快照共 12 项测试通过。

这能避免正常模型思考期间（约 5–60 秒）的空闲断连。首次冷连接、超过客户端 60 秒保活窗口的连接，以及模型服务自身首字等待仍需分别计时，不能算作全部消除。

远端部署尚未执行。定点脚本会核对桌面 hostname 和源文件 SHA-256，保留原文件备份后增加保活参数并重启 `openbox-action-server`。2026-09-18 的连接故障另行定位为本地 Session Manager 会话失效，已通过提前换新隧道修复；该修复无需更改远端服务，也不代表上述空闲连接延迟已经消除。
